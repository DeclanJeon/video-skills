# Video skills orchestration design

## Current approved intent (2026-11-28)
Use the current video-skills directory as the canonical source for every registered agent. A single automatically discoverable `video-skills` entry owns requested scope and resumes. It explicitly reads the existing preproduction, production and postproduction phase instructions; their runtime files and disabled flags remain unchanged. Replace obsolete connection instructions and shared cached availability claims, not department implementations. No installation, external generation, upload or publishing is authorized by this documentation sync.

## Approaches
- Register all departments automatically: rejected; exposes disabled/unreleased departments and conflicting finished-video routing.
- Reuse creative-production: rejected; user explicitly replaces it.
- Chosen: one public orchestrator, direct file reads of existing phase entry points and their relative resources. Preserve phase gates and authoritative ledgers. Register the orchestrator across existing agent skill roots.

## Request contract
- Preproduction only: production-director through requested design/prompt endpoint; no paid production.
- Production only: production-supervisor using validated preproduction inputs; missing inputs are blockers or receive only expressly authorized preparation, not an invented completed preproduction.
- Both: preproduction then production without routine phase approval prompts.
- Postproduction only/editing: read video-postproduction-skills/SKILL.md and validate actual Handoff plus IntakeRequest inputs; do not rerun upstream phases or invent missing approvals.
- Final video/nonstop: preproduction → production → current post entry, following references/postproduction-slot.md through actual intake, work, current QA and local delivery. Production handoff is not a final master. Missing inputs/tools/authority/QA retain the requested target with the exact blocker and restart point.
- Single artifacts and existing work: route to relevant department or resume actual ledger; do not restart a completed phase or create unwanted project scaffolding.
- Nonstop means continued execution within actual authority. Spend, transfer, rights, publishing and unavailable tools remain explicit gates. Already approved scope is reused, not repeatedly requested.

## Registration and legacy policy
Back up settings, workflow instructions and original symlink targets before mutation. Retire old planning/router registrations that resolve into contents-production-skills; retain provider/equipment skills needed by new packages and unrelated standalone image/web skills. Remove links only (never legacy source). Shared ~/.agents and existing Pi, Codex, Claude, Gemini and OpenCode skill roots receive one video-skills symlink. Remove stale Pi positive legacy entries and exclusions for newly installed entry; use existing discovery and check collision diagnostics. Update shared workflow pointer. Preserve original disabled flags in department sources; orchestrator reads explicit file entry points as delegated phase instructions, not automatically invoked commands.

## Completion evidence
Validate current routing references, local resource paths and byte identity across existing registration roots; compare protected phase package bytes before/after. No external generation or installation of runtime dependencies is authorized. Static routing checks and synthetic boundary tests do not demonstrate agent compliance, actual full-pipeline video production or human audiovisual QA.
