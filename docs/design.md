# Video skills orchestration design

## Approved intent
Replace legacy creative-production routing in shared and agent registrations. A single automatically discoverable `video-skills` entry owns scope and resumes. Sources remain in this directory; the two existing packages remain unchanged. User approved design QA then execution. Postproduction is being authored elsewhere: reserve a connection only; do not modify, move, implement or install that package.

## Approaches
- Register all departments automatically: rejected; exposes disabled/unreleased departments and conflicting finished-video routing.
- Reuse creative-production: rejected; user explicitly replaces it.
- Chosen: one public orchestrator, direct file reads of existing phase entry points and their relative resources. Preserve phase gates and authoritative ledgers. Register the orchestrator across existing agent skill roots.

## Request contract
- Preproduction only: production-director through requested design/prompt endpoint; no paid production.
- Production only: production-supervisor using validated preproduction inputs; missing inputs are blockers or receive only expressly authorized preparation, not an invented completed preproduction.
- Both: preproduction then production without routine phase approval prompts.
- Final video/nonstop: both then postproduction if a real installed implementation exists. Post slot initially unconfigured. Production handoff is not a final master. If unavailable retain requested final target, report blocked and save exact restart point, not done.
- Single artifacts and existing work: route to relevant department or resume actual ledger; do not restart a completed phase or create unwanted project scaffolding.
- Nonstop means continued execution within actual authority. Spend, transfer, rights, publishing and unavailable tools remain explicit gates. Already approved scope is reused, not repeatedly requested.

## Registration and legacy policy
Back up settings, workflow instructions and original symlink targets before mutation. Retire old planning/router registrations that resolve into contents-production-skills; retain provider/equipment skills needed by new packages and unrelated standalone image/web skills. Remove links only (never legacy source). Shared ~/.agents and existing Pi, Codex, Claude, Gemini and OpenCode skill roots receive one video-skills symlink. Remove stale Pi positive legacy entries and exclusions for newly installed entry; use existing discovery and check collision diagnostics. Update shared workflow pointer. Preserve original disabled flags in department sources; orchestrator reads explicit file entry points as delegated phase instructions, not automatically invoked commands.

## Completion evidence
Validate routing scenarios, resource paths, unique discovery and rollback inventory; compare protected phase package bytes before/after. No external generation or installation of runtime dependencies is authorized by this configuration migration. Postproduction reserved state is a passing integration condition, not evidence of final-video capability.

## QA focus
Nonstop vs authority; production-only missing inputs; placeholder post reported blocked; symlink source preservation; shared duplicate discovery; disabled department routing; relocated sibling paths and legacy equipment references.

## Design QA resolutions (2026-11-26)
The independent review is qa/design-review.md; its six P1 findings are accepted.
1. The orchestrator's assigned phase boundary overrides imported director P6 generation/P7 routing and legacy equipment callbacks. Director owns preproduction only; supervisor owns actual generation and take QA; no legacy P7 fallback. Safety requirements remain binding. Missing capability is a truthful blocker.
2. The handoff is an explicit agent-authored, verified production Project projection from actual board CSV/header, script, current ledger and mandatory dependency closure. references/phase-contract.md specifies source locators, unchanged IDs/pins, read-only validators, immutable origin and exported coverage. Never pass the artifact ledger directly as a Project. Unmapped requirements block G0. A synthetic actual-Ledger+CSV boundary test validates projection using the existing derive/export functions; it is not an automatic general CSV converter or creative QA.
3. Use separate mutable preproduction ledger.json and production-ledger.json from first initialization. If historical files already combine namespaces, block legacy writes; resume production read-only/status and request a preservation/migration seam before preproduction revision. Serial writes alone are not safe.
4. Keep equipment/history closure; retire old planners. Retain compatibility auditor scripts at the historical video-production-assets registration path as a resource-only directory with no SKILL.md. Canonical legacy root is ../../contents-production-skills from each relocated phase package (../contents-production-skills from this orchestrator root).
5. Equipment consumes the new coordinator's call sheet and returns without calling creative-production; retain model/schema/authority gates. Shared workflow pointer applies this overlay to video-related equipment requests as well.
6. Distinguish sources_ready, g5_blocked/handed_off and master_delivered. Post unconfigured can block G5 receipt; never fabricate receipt for the placeholder or downgrade final target to source delivery. An actual authorized external receiver may satisfy G5.

For this case use the existing CoverageEnvelope branch with cut-scoped requirement keys, original dialogue IDs/ranges in locators and immutable provenance sidecar, all original cut/panel/beat/cue/asset obligations retained.
