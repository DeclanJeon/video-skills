# 영상 제작 판단 통합 Implementation Plan

> 실행: executing-plans로 직접 수정. 별도 평가자는 비변경 평가만 한다.

**Goal:** 기존 제작 판단으로 해결되지 않는 사례만 보강한다.
**Architecture:** 설계의 소유자가 원본 규칙 한 곳을 관리한다. QA가 설계 규칙을 복제하지 않고 실제 관찰 결과를 해당 부서로 반환한다.
**Tech Stack:** Markdown 부서 지침, 로컬 사례 평가, 기존 pytest.
**Spec:** `../specs/2026-11-28-visual-decision-integration-design.md`

## Global Constraints
최상위 라우터/등록/승인/원장/스키마 불변. 실행·비용·업로드·배포 없음. 케이스는 합성 시나리오이며 실제 영상 납품이 아니다. 기존 미추적 계획서 2개와 사운드 목표는 대상 밖이다.

## Review Focus 및 작업지시

입력은 각 행의 대조쌍으로 고정한다. 선행 조건은 현재 부서 지침만 제공한 읽기 전용 응답이다. 단순히 기대 답을 알고 있는 것과 반복 가능한 근거가 있는 것을 구분한다. 기존 동작이 충분한 행은 수정 없이 보존한다.

| 작업 | 수정 후보(부서 SKILL.md) | 입력 → 기대 판정 / 금지 반례 |
|---|---|---|
|T1|lighting-director(노출 예방), 프로 take-reviewer(결함 분류)|실물 MORI 30 mL, 후면 미노출. 반사로 판독 불가 → 노출/구도 담당, 선명한 MOR1 80 mL → 실제 기준 사진과 입력 결속·재현 담당. 원인 미확정 시 임의로 재생성하지 않는다. 보이지 않는 후면은 검사하지 않는다.|
|T2|video-prompt-engineer|고정 셀피 두 문장은 실측·한도 안에서 같은 셋업 후보. 돌아서 가방에서 첫 화면에 없던 병을 꺼내면 몸/손/제품 가시 상태에 맞는 참조·보조 키프레임 또는 분할. 한 모델 강제 금지.|
|T3|프로 generation-operator|이전 슬롯 인물→병, 현재 병→인물. 제출 전 실제 선택 순서와 프롬프트를 대조해 역할을 교정. 새 전역 번호표를 만들지 않는다.|
|T4|cinematographer|옆 이동의 전후에 가려진 문이 보이는가. 감정을 위한 고정은 보존하고 정보 공개를 모든 무빙의 의무로 만들지 않는다.|
|T5|film-editor|같은 행동을 반복하는 두 컷 중 삭제해도 정보를 잃지 않는 컷은 병합/삭제 후보. 대비·감정·시간 변화가 있는 반복은 유지. 편집 의도 무시한 자동 삭제 금지.|
|T6|world-designer/assets/WLD-template.md|‘수선하는 마을’에서 근거 없는 새 작업대는 세계 규칙에 대조. 감독 승인 예외는 근거·범위와 함께 유지. 설정을 전역 금지로 만들지 않는다.|

## 실행 순서
- [x] S1 설계 표의 번호를 로컬 index.json과 대조하고 중복 파일 2쌍을 sha256sum으로 확인한다.
- [x] S2 T1–T6에 대한 기준선 응답을 기록한다. 규칙을 우선 검색하고 같은 지침이 다른 정본에 있으면 재서술 대신 기존 연결을 사용한다.
- [x] S3 누락 행만 해당 부서 절차에 조건부로 반영한다. 각 실제 diff를 T 번호와 연결하고 나머지는 건너뛴 이유를 남긴다.
- [x] S4 수정 사실을 알려주지 않은 평가자가 동일 입력에 답하도록 하고 전후 차이를 기록한다. 같은 기준으로 ‘기존 통과’도 재확인한다.
- [x] S5 0–5초 고정 셀피 / 5–10초 가방 / 10–15초 라벨의 텍스트 패킷에서 소유자와 정보 흐름을 추적한다. 관련 변경 패키지에서 `python3 -m pytest -q tests` 실행 및 `git diff --check`. 환경 차단은 숨기지 않는다.
- [x] S6 독립 평가자가 실제 파일 해시와 기록을 대조한다. 결함은 반영 후 재검수하고 차단 0일 때만 목표를 완료한다.
