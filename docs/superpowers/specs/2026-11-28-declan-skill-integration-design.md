# Declan 자료의 스킬 반영 설계

상태: **사용자 승인 후 스킬 문안 반영** (2026-11-28). [반영 결과·검증 한계](../../../qa/declan-skill-integration.md). 행동/영상 품질 개선은 별도 검증 대상이다.

## 1. 목표와 근거 범위

Declan 방에서 확인한 공개 자료 중 기존 video-skills에 없는 판단 방법만 기존 담당 스킬에 통합한다. 자료를 많이 설치하거나 규칙 수를 늘리는 것이 목표가 아니다.

[Declan 한정 조사](../../research/2026-11-28-declan-only-candidates.md)가 출처·저장 날짜·조회 범위의 정본이다. 실제 날짜 있는 메시지는 11/20~11/27이며, 한 달 전체를 확보한 조사가 아니다. 다른 방에서 가져온 Prompt Motion·Unlimited·화면비/모션 트랜스퍼 실패담은 이 설계 근거에서 제외한다.

## 2. 접근 선택

| 접근 | 장단점 | 제안 |
|---|---|---|
| 외부 스킬팩을 그대로 설치 | 넓은 기능, 중복 라우팅·도구·라이선스·하네스 의존성 증가 | 제외 |
| 지침을 모든 부서에 반복 추가 | 발견은 쉬워지나 같은 의미의 정본이 여러 개 생김 | 제외 |
| 기존 담당 스킬에 조건부 판단만 통합 | 기존 산출물·권한·실행기를 유지하며 작은 차이를 검증 가능 | **추천** |

반영 대상은 핵심 2개(A/B), 조건부 참고 1개(C)다. 실제 수정은 기존 지침으로 같은 입력을 시험해 누락이 재현된 항목만 한다. 이미 처리되는 항목은 **변경 없음**이 성공이다.

## 3. 반영 항목 A — 여러 정보 모션의 시선 위계

### 적용 조건
제목·도형·수치·설명 라벨 등 여러 요소가 움직이고, 서로 다른 강조가 같은 시점에 관객의 시선을 경쟁적으로 요구하는 컷. 단일 강조, 일반 대화, 의도된 혼란/동시성이 승인된 장면에는 새 순서 규칙을 강제하지 않는다.

### 기존 내용과 순증
- 기존: 진입/이탈·홀드·시간 근거, 설명 모션의 시작 신호·대상/변화·지속시간·종료 상태.
- 추가할 판단: **그 순간 무엇을 먼저 읽어야 하는지**, 보조 움직임이 중심 설명을 방해하는지, 언제 정착해 다음 설명에 자리를 내주는지.
- 위 시간 계약을 새 필드나 별도 표로 반복하지 않는다.

### 소유와 반영 파일
[프리 film-editor/SKILL.md](../../../video-preproduction-skills/film-editor/SKILL.md)의 기존 설명 모션 지침에 조건부 보강한다. [기존 승인 설계](2026-11-27-episode-handoff-motion-design.md)의 film-editor 범위를 확장하는 제안이며 회차 연결 범위는 건드리지 않는다.

**예상 문안**
> 여러 정보 요소의 움직임이 시선을 경쟁하면, 그 구간에서 먼저 읽을 중심 요소를 정하고 보조 요소의 강조·시작·정착 순서를 기존 편집 레이어에서 조정한다. 승인된 동시 강조의 목적이 있으면 그 의도를 보존한다.

예: 제목이 읽히기도 전에 설명 카드들이 튀어나오는 컷은 제목 읽기 → 첫 카드 강조 → 카드 정착 후 다음 카드의 순서로 제안한다. 고정 대기시간을 임의로 넣는 대신 승인된 러닝타임·읽기량·발화 근거에서 시간을 정한다.

### 가져오지 않을 것
LottieFiles의 UI용 ms 표, 1/3 수치, 항상 ambient를 추가하는 규칙, 특정 easing·스프링 실행 약속, Creator MCP 설치. 일반 드라마의 연기·카메라 규칙으로 확장하지 않는다.

### 출처
[Declan에 저장된 발견 글](https://x.com/Jonnyhlkw/status/2125801726603407484) → [LottieFiles SKILL.md](https://github.com/LottieFiles/motion-design-skill/blob/d77a9fc8cb371cab1ba5420df5bfd232cd14c9bb/skills/motion-design/SKILL.md) 및 [choreography](https://github.com/LottieFiles/motion-design-skill/blob/d77a9fc8cb371cab1ba5420df5bfd232cd14c9bb/skills/motion-design/director/choreography.md). 원문을 복사하지 않고 영상에 필요한 판단만 재서술한다.

## 4. 반영 항목 B — 도식의 의미·공개 순서

### 적용 조건
절차·관계·흐름을 설명하는 도형/연결선이 있고, 공개 순서나 연결 방향이 의미를 바꾸는 컷. 도식 없는 작품에는 적용하지 않는다.

### 기존 내용과 순증
- 기존: 모션 타이밍·자막 동기·가림 검사·승인된 공개 순서 보존.
- 추가할 판단: **지금 설명하는 대상과 관계가 무엇인지**, 연결선이 실제로 그 대상을 잇는지, 색의 의미가 장면 중 바뀌는지, 관계 공개가 설명과 맞는지.
- 승인된 결과 선공개/역순 설명은 오류가 아니다. 극중 인과·설명 순서·관객 공개 순서를 혼동하지 않는다.

### 소유와 반영 파일
A와 같은 film-editor 지침에서 처리한다. A는 주목 순서, B는 관계의 의미를 맡으므로 같은 시간 계약을 중복 작성하지 않는다.

**예상 문안**
> 관계나 절차를 설명하는 도식은 승인된 설명·공개 순서에 맞춰 대상과 연결의 등장 신호를 정하고, 연결 방향과 색의 의미가 유지되는지 확인한다. 계획 시각과 실제 발화 시각을 구분한다.

예: 저장 → 검증 → 발송을 설명하는 컷에서 발송 화살표가 검증 이전에 공개돼 즉시 발송처럼 보이면 순서를 교정한다. 반대로 승인 각본이 결과 화면부터 보여주면 그 구조를 유지하고 해당 구간의 설명과 관계만 일치시킨다.

### 가져오지 않을 것
모든 도식에 nodes→edges→labels 일률 강제, 고정 노출시간, 웹 타이머·Remotion 도입, 존재하지 않는 단어별 발화 시각, 숫자·그래프의 사실성을 이 검사만으로 인증하는 규칙.

### 출처
[Declan 발견 글](https://x.com/Yarad_ai/status/2121715992757981275) → [iart diagram-animation source](https://github.com/iart-ai/explainer-video-skills/blob/3c13a1bc360c08503f24f9c9a99fda6d3d35de56/skills/diagram-animation/SKILL.md).

## 5. 반영 항목 C — 동일 내용의 룩 비교 (조건부·후순위)

### 적용 조건
사용자가 아직 시각 스타일을 결정하지 못했고, 기존 레퍼런스가 서로 다른 이야기·구도여서 룩 자체를 공정하게 비교하기 어려울 때. 이미 스타일이 잠긴 작품에는 다시 선택을 요구하지 않는다.

### 기존 내용과 순증
- 기존: BMK/BOR 비교, 스타일 잠금, 불확실한 구간의 저비용 시험.
- 순증: 서로 다른 내용의 demo를 스타일 우열 근거로 삼지 않고, 비교를 방해하는 내용/길이/화면비/구도 등의 차이를 통제하거나 비교 한계로 표시한다.
- 이것은 시장 성과 비교와 구분한다. 스타일 선호 비교가 조회수·제작 품질·모델 성능 증거는 아니다.

### 소유와 반영 파일
[concept-benchmark/SKILL.md](../../../video-preproduction-skills/concept-benchmark/SKILL.md)의 레퍼런스 비교 절차에 짧은 조건부 지침을 넣는다. BRF/BMK/BOR를 그대로 사용한다.

**예상 문안**
> 룩 선택이 미정이고 내용 차이가 비교를 방해하면, 가능한 동일한 짧은 내용·구도·길이·화면비의 후보로 비교한다. 통제하지 못한 차이는 비교 한계로 남기고, 이미 확정된 스타일을 다시 선택하게 하지 않는다.

기존 승인 샘플이 있으면 재사용한다. 샘플이 없으면 비교 한계와 필요한 입력을 반환한다. 새 실제 생성이 필요하면 감독/오케스트레이터가 기존 단계·권한에 따라 배정하며, concept-benchmark가 생성/결제/전송을 독자 실행하지 않는다. 모든 작품에 2개 샘플 생성을 의무화하지 않는다.

### 출처와 한계
[Declan 발견 글](https://x.com/Yarad_ai/status/2123056076723556672) → [Video Studio Kit](https://github.com/owlinthebarnai/video-studio-kit). README의 preview는 일부만 같은 이야기를 사용한다. kit의 모든 스타일·의존성·라이선스를 한 번에 채택하지 않는다.

## 6. 변경 경계와 정본

| 경로 | 후속 반영 범위 |
|---|---|
| video-preproduction-skills/film-editor/SKILL.md | 기존 설명 모션 지침에 A/B를 합쳐 짧은 조건부 단락. 기준선에서 누락된 것만 반영 |
| video-preproduction-skills/concept-benchmark/SKILL.md | C의 필요가 재현될 때 비교 절차에 한 단락 |
| video-postproduction-skills/motion-compositor/SKILL.md | **변경 없음**. 기존 timeline/recipe·native 지원 확인·QA 반환 계약으로 설계를 실행 |
| 기존 CNT/편집 레이어·BRF/BMK/BOR | 형식 변경 없이 해당 판단과 한계를 기록 |
| 루트 SKILL.md·전역 등록·공통 지침·모델/설치/승인·schema·원장 | 변경 없음 |

운영 규칙은 담당 SKILL.md 한 곳에 둔다. 출처/분석은 조사 문서에 남기며 실행 스킬에 조사 전체를 붙이지 않는다. 후반에 입력이 전달되지 않는 실제 문제가 재현되면 별도 연결 결함으로 다루고 같은 규칙을 여러 부서에 복사해 해결하지 않는다.

후반은 설계를 현재 지원되는 native primitives/recipe로만 구현한다. 구현 불가한 효과는 근사 재현 범위 또는 차단으로 반환하며 사용자 승인 없이 편집 의미·도구를 바꾸지 않는다. 이 설계가 linear keys 외 임의 모션 기능을 인증하지 않는다.

## 7. 수용 기준 — 구현 전후 같은 입력으로 확인

| 사례 | 기대 결과 |
|---|---|
| A1: 서로 다른 강조가 제목 읽기를 방해 | 중심/보조와 필요한 순서 조정을 설명하고 기존 레이어에 반영 |
| A2: 단일 강조만 있는 정상 컷 | 불필요한 모션 계층/양식/정지시간 추가 없음 |
| A3: 혼란을 의도한 동시 강조가 승인됨 | 장면 의도를 보존; 임의 순차화 없음 |
| B1: 절차와 반대로 연결선 공개/방향이 바뀜 | 잘못 읽히는 관계와 최소 수정 지점을 식별 |
| B2: 승인된 결과 선공개 | 역순이라는 이유만으로 반려하지 않음 |
| B3: 도식 없는 대화 컷 | 도식·색 체계·추가 항목을 요구하지 않음 |
| C1: 내용이 다른 demo로 룩 우열 단정 | 비교 한계와 통제할 요소를 구분; 제작/성능 우열을 확정하지 않음 |
| C2: 이미 스타일 확정 | 재선택·새 샘플 생성 제안 없음 |
| C3: 비교 샘플 부재·생성 승인 없음 | 누락 근거/필요 입력만 반환, 생성·설치·결제 호출 없음 |
| 실행 경계: unsupported native motion | 지원 여부·대안·승인 필요 상태를 반환; 성공/완료를 만들지 않음 |

현재 지침의 결과가 이미 기대를 충족하면 해당 항목은 no-op 처리한다. 보강이 필요하면 같은 입력으로 전후를 비교하고 비대상 장면도 재검사한다. fresh-context 에이전트 검사는 위임 승인이 있을 때 수행한다. 문자열 존재/문서 구조 검사만으로 에이전트 준수나 영상 품질 개선을 주장하지 않는다.

문서/역할 변경 시 기존 프리 패키지 검사와 회귀를 실행한다. 실제 모션 품질은 승인된 도구로 만든 결과의 필요한 시점·전구간 재생으로 별도 확인하고, 기존 전체 QA를 축소하지 않는다. 이번 설계 단계에서는 테스트/렌더를 수행한 것으로 기록하지 않는다.

## 8. 이번에 반영하지 않는 것

이미 반영된 복수 피치·AU·시간 블록·Unlimited 검사; 기존 별도 회차/편집 복구 설계; AutoClip 재편입; 실제 데이터 그래프; 새 TTS/ASR·Colab·Flow/Sume·SpriteCast/blueprint·FastFrames 설치/연결; 공개 수익·품질·가격 주장을 기본값으로 쓰는 것.

## 9. 승인 후 순서

1. 기존 승인된 설명 모션 작업과 겹치는 A/B를 하나의 범위로 조정한다. 같은 시작/종료/지속시간 변경을 두 번 실행하지 않는다.
2. 위 사례의 기존 지침 판단을 확인하고 변경/no-op을 항목별 결정한다.
3. 필요한 담당 SKILL.md만 최소 수정하고 같은 입력/비대상 입력으로 재검사한다.
4. 실제 변경 파일·정적/행동/렌더 검증을 구분해 보고한다.

현재 결론: **A/B 핵심 보강, C 조건부 보강의 설계**. 구현·새 설치·비용·외부 생성·위임·커밋·푸시는 이 문서 작성으로 승인되지 않는다.
