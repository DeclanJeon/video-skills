# 00 — 목표·접근·역할

상태: 설계 제안. 역할 이름과 내부 계약은 부모의 제안이며 구현되거나 사용자가 문서 전체를 승인한 상태가 아니다.

## 1. 목표와 단계 분리

프리프로덕션이 정한 이야기·인물·에셋·보드·프롬프트, 프로덕션이 검수/채택한 실제 소스를 받아 **편집 가능한 작업 프로젝트와 검수된 최종 마스터**를 만든다. 파일을 단순 연결하거나 도구의 export 성공을 작품 완성으로 취급하지 않는다.

```
승인된 production Handoff + 고정 upstream 요구/인덱스
  → 필요한 도구 탐지/미설치 설치·설정/실행 검증(PG-E)
  → 수령/권리/기술 검사 → 편집 의도와 변경안 승인
  → FilmCraft 편집 정본 투영
  → EffectCraft 합성·타이틀 / 색보정 / SoundCraft 음향 / 자막
  → 버전 고정 검수본 → 실제 시청·청취와 수정
  → 승인된 설정의 최종 렌더 → 최종 파일 QA → 납품 패키지
                                      └→ 별도 승인한 숏폼 변형
```

- preproduction은 설계 SSOT, production은 채택된 source/take/range와 원격 생성 사실을 소유한다.
- postproduction은 편집 결정·변환·프로젝트·마스터·분야별 수정/QA를 소유한다. production 과거 요청이나 채택 기록을 수정하지 않는다.
- 최종 업로드·계정 소통·게시 일정은 별도 publishing 단계다. 납품과 게시 권한을 합치지 않는다.
- 고장난 얼굴/접촉/필수 행동/대사를 ‘후반에서 고치면 됨’으로 자동 수락하지 않는다. 승인되지 않은 재생성·보간·voice clone은 실행하지 않고 적절한 상위 소유자에게 반환한다.

## 2. 선택한 접근

사용자가 **자동 실행 중심 + 설치 Craft 우선**을 선택했다. 사람에게 편집안만 넘기는 접근은 기본이 아니며, 다음 두 극단도 기본으로 삼지 않는다.

| 접근 | 장점 | 배제/선택 이유 |
|---|---|---|
| 도구 중립 편집 정본 + Craft 실행 Adapter | 자동 편집/렌더, 추적/재개, 작업별 다른 실행자 사용 | **선택 방향**. adapter별 실제 지원과 손실을 따로 검증해야 한다. |
| 특정 편집기의 native 프로젝트만 정본 | 수동 편집 기능과 가장 밀접 | 프로젝트 전체를 특정 버전/앱에 종속시키고 타 도구 손실을 숨기기 쉬움. native 작업 사본은 유지하되 기본 정본은 아님. |
| AutoClip/FFmpeg 하나로 모든 후반 대체 | 단순한 클리핑/변환에는 편리 | 연속 서사 coverage·전문 합성/음향·편집 프로젝트를 대체한다고 검증되지 않음. 선택 모듈/기술 보조로 한정. |

실행 도구가 바뀌어도 승인된 편집 의도·시간·계보·검수 기준은 유지한다. 서로 다른 구현의 같은 이름 효과를 시각적으로 같다고 가정하지 않는다. 자동 실행은 무승인 creative 변경이나 무인 게시를 뜻하지 않는다.

## 3. 제안 역할 8개

| 역할 ID | 책임/입력 | 산출물/금지 |
|---|---|---|
| `postproduction-supervisor` | 수령 계약, edit brief, 권한, 작업 DAG, 환경 준비 Module, 단일 writer | 필요한 프로그램의 설치·설정·실행 준비와 작업 재개, 승인된 work order/영향 범위/정확한 진행률. 유일한 정본 commit 소유자. |
| `picture-editor` | source/select range/요구·사건·대사 anchors | assembly/rough/fine cut 결정, conform, 변경 영향. 의미를 삭제한 축약·가짜 handle 금지. |
| `motion-compositor` | 승인된 FX/타이틀/마스크와 보호 영역 | EffectCraft 작업, alpha/plate·모션 결과와 recipe. 무승인 정체성 변경/외부 모델 금지. |
| `color-finisher` | look SSOT, 실제 색 metadata, reference | shot match/grade/색 변환 기록. 미검출 metadata를 검출 사실로 기록하지 않음. |
| `sound-editor-mixer` | 실제 음원/트랙, cue, 대사, 권리, 목표 음량 | dialogue/ambience/SFX/music 편집·믹스·측정. 존재하지 않는 stem·새 목소리 금지. |
| `caption-editor` | 승인 원문/화자, 실제 발화·편집 시간, style | 원문/번역/강조를 구별한 cue·자막/그래픽. ASR를 승인 원문으로 자동 덮어쓰기 금지. |
| `finishing-operator` | 현재 승인 timeline·분야별 결과·delivery profile | native save/export, 검수본/마스터/납품 파일·기술 증거. 자기 export를 의미 QA PASS로 선언하지 않음. |
| `postproduction-qa` | 고정된 실제 검수 파일·범위와 기준 | 시간코드 기반 시청/청취/분야별/전체 판정. 정지 이미지나 모델 설명으로 동영상/청취 PASS를 가장하지 않음. |

역할은 반드시 별도 프로세스/에이전트일 필요가 없다. 이 설계가 실제 에이전트 추가 실행 권한을 부여하지 않는다. 분야별 실행자는 수정안을 반환하고 총괄이 같은 원장에 반영한다. QA 역할은 실행자와 판정 책임을 구분하되 실제 시청/청취 능력의 확보가 선행 조건이다.

## 4. 권한과 비목표

`EditAuthority` 제안은 프로젝트/branch/요구 revision, 허용 source/range, 편집 종류(구간·순서·재구도·속도·효과·색·자막·음향), backend/버전, 출력 위치, 전송 목적지/자료 종류, 예산/추가 시도, 검수·납품 범위를 결속한다. production의 ‘생성·참조 전송 승인’을 새로운 후반 도구/서비스 전송 승인으로 바꾸지 않는다.

기본은 로컬 편집, 원본 비덮어쓰기, 별도 작업 사본, 미승인 외부 미디어 전송/게시 비활성이다. 사용자는 필요한 프로그램이 없으면 스킬이 설치하도록 보완 요구했다. 최신 사용자 지시에 따라 먼저 시스템과 동일 프로그램 설치 여부를 점검하고, 새 설치가 필요하면 무료 도구라도 사용자에게 구체적 계획을 묻고 동의 후 수행한다. 기존 설치는 재사용한다. 새 결제·본인 로그인/약관·관리자 권한/재부팅·공유 환경 변경·모델/클라우드 전송은 그 동의 범위에 포함됐는지도 확인한다. [환경 준비 계약](06-environment-and-installation.md)을 따른다. 현재 회차는 설계 작성/보완 권한이며 실제 설치·실행을 시작한 상태가 아니다.

납품은 작품의 승인 형식을 따른다. 주 마스터와 숏폼은 별도 branch/profile/QA로 관리하고, 쇼츠 템플릿을 모든 드라마/장편에 강제하지 않는다. 의미를 바꾸는 파생 컷은 원 마스터 승인으로 자동 승인하지 않는다.

## 5. 성공과 실패의 정의

성공은 ‘승인된 이야기와 source를 보존한 편집 결정 → 실제 도구 결과 → 현재 검수 → 정확한 최종 파일’이 연결되는 것이다. 잘못된 소스·오프라인 placeholder·무음·자막 잘림·필수 장면 삭제·stale 판정·라이선스 누락·부분 렌더를 감춘 export는 실패다. 프로그램 설치/명령 개수/문서 존재를 작품 품질이나 구현 완료율로 세지 않는다.
