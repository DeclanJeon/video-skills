# 로컬 후반작업 운영

## 권한·범위
로컬 소스 패키지이며 global skill 등록/공개 배포/게시 기능은 없다. `manifest.json`의 여덟 역할과 루트 entry는 disabled-auto-invocation이다. 설치된 기존 Craft의 synthetic 작업, 계약 fixture와 reported semantics를 검증한다. 실제 신규 vendor 설치·다른 OS·원본 템플릿 호환·인간 지각/법적 권리/설치 응답 발급자 진위는 인증하지 않는다. 상위 video-skills와 production/preproduction 패키지는 수정하지 않는다.

기존 동일 프로그램·CLI/PATH/package/desktop/알려진 위치를 점검해 충분하면 재사용한다. unknown≠absent. 새 프로그램/font/plugin/model/dependency가 꼭 필요하면 정확한 host/계획을 실제 질문하고 명시 동의 후에만 download-for-install/설치한다. goal 활성화/free/project-local/`--yes`는 동의가 아니다.

## 입력과 CLI
`python3 scripts/postproduction.py --help`와 각 command `--help`가 인자 정본이다. 주요 외부 입력의 실제 strict runtime schema는 `schemas/`에 있다. 예시는 형식 설명일 뿐 승인/권한이 아니다.

- 실제 production Handoff, 요구 snapshot/schema/brief/profile/authority/소스 승인과 full original denominator를 `IntakeRequest`로 수령한다. 단독 Handoff는 충분하지 않다.
- `intake PROJECT.json --request REQUEST.json`, `validate PROJECT.json`, `plan PROJECT.json`/명시 `--proposal`/`--commit`, `progress PROJECT.json`.
- 명시 WorkOrder의 `prepare PROJECT.json ORDER.json`이 reservation을 기록한다. 출력 job ID로 `run`, `observe`. historical receipt만으로 신규 dispatch하지 않는다. 실제 result/materialization/current QA/adoption은 다른 상태다.
- `review PROJECT.json REPORT.json`은 고정 final pin의 보고된 범위와 PG를 검사한다. `deliver PROJECT.json CONTRACT.json`은 receiver/권리/current QA/모든 필수 파일을 다시 검사해 로컬 no-clobber bundle을 만든다.
- `invalidate PROJECT.json PINS.json`, `intake ... --revision REVISION.json`은 narrow API로 계보/과거 snapshot/jobs를 보존한다. JSON에 succeeded/delivered를 수동 추가하지 않는다.

## Native qualification
FilmCraft initial route는 실제 CFR/same geometry·rate/H264 MP4 hard cuts와 native readback/독립 full decode다. EffectCraft는 native solid/linear motion/literal English·Korean text와 전체 RGBA sequence·정확한 기존 font 검사다. SoundCraft는 실제 독립 WAV/FLAC stem inventory와 WAV/cue/sample/gain/stereo mix/bounce다. Mono-center 실제 -3dB, arbitrary resample/AAF는 qualified가 아니다.

Finishing은 명시 artifact IDs/FinishingRecipe로 actual picture/PNG plates/text/mix를 실제 FilmCraft에 결합한다. prepare·raw reservation 실행·현재 materialization/QA는 같은 finishing admission 계약으로 work의 domain/backend/full source/authority, recipe의 exact pin/branch, 실제 required dependencies와 immutable input projection을 결속한다. recipe label과 work ID 자체는 같을 필요가 없고, producer의 adoption registry flag만 바뀌는 것은 native input 변경이 아니다. 재사용 picture는 destination branch와 실제 source 순서/범위/tick map이 같아야 한다(같은 내용의 clean branch는 허용). mix의 exact picture lock/fps/sample count/layout, plate/caption의 실제 consumed source→master map도 결속한다. 과거 잘못 만든 materialization proof도 현재 QA에서 이 조건을 다시 검사하며 성공 기록/bytes는 삭제하지 않는다. color는 actual metadata/unknown·explicit assignment/target의 구분이며 실제 임의 LUT/grade/지각 shot-match 보증이 아니다. absent Paperlogy/Hakgyo font를 다른 font로 몰래 대체하지 않는다.

## 복구·소유권
프로젝트 JSON의 기존 production public lock inode와 byte CAS를 공유한다. parent 총괄만 post namespace를 commit하고 foreign 데이터를 보존한다. mutable diagnostics보다 native/install facts를 먼저 fsync한다. 진단 저장 실패로 알려진 PID/job을 지우지 않는다.

unknown/live/partial/이미 완료한 native job은 무조건 재실행하지 않는다. 실제 process·workspace·source·receipt를 대조하고 stale 산출물은 현재 채택에서 제외하되 과거 사실/원본 bytes는 남긴다. actual-consumed artifact는 producer lineage까지 소비한다. unrelated source 손실은 독립 분야 작업을 막지 않지만 full final gate는 닫힌다.

Portable 추출은 실제 regular-file payload 전체를 CLI-first 목록으로 반환하고, 복구는 archive hash·전체 target 대조 후 같은 목록을 재생성한다. symlink/hardlink 의존 layout은 별도 검증 adapter 없이는 publish 전에 명시 거절하며 기존 unknown/foreign target은 보존한다. Portable smoke는 이 실제 공급/복구 목록 전체를 정확한 readonly mounts로 노출하여 sibling library/resource를 보존하되 상위 home/target 전체를 열지 않는다. 시스템 밖 명시 실행 파일도 정확한 파일만 readonly mount한다. 임의 미신고 의존성의 자동 탐지/설치는 하지 않는다.

Installer recovery는 정확한 재동의·host/tool lease와 physical process/cache/source/entire target inspection 후 cached verified artifact 재사용 또는 completed target 재검증만 수행한다. foreign lock/사용자 앱/기존 unknown target은 보존한다. rollback은 live process 없는 자신이 새로 만든 정확한 payload만 지우며 기존 repair/upgrade/user-edited target은 임의 삭제하지 않는다.

## QA·납품
`technical_fixture`는 실제 native 기술 시험 + 보고된 의미 계약 fixture이며 실제 인간 시청/청취가 아니다. `reported_not_authenticated`는 공급된 보고서와 exact scope를 검사할 뿐 발급자 진위를 보증하지 않는다. metadata/contact sheet만으로 full playback/listening PASS를 만들지 않는다.

각 required occurrence, fixed final file, current source/approval/recipe/native/sidecar/producer, conditional 적용·부작용·현재 범위를 확인한다. scheduled/applied 메모는 해소가 아니다. preview QA를 다른 encode에 승계하지 않는다. work/coverage/fix/technical QA/formal QA/rendered/history/delivery 분모를 섞지 않는다. 현재 납품 완료는 main과 모든 계약 variant의 최신 QA·권리·의존성 및 bundle hashes를 다시 검사한다. required variant invalidation이면 현재 완료 수는 내려가지만 과거 납품 기록/bytes는 보존한다.

명시 profile.loudness가 있으면 최종 파일을 기존 FFmpeg EBU R128/oversampled true-peak로 독립 전구간 측정하고 PG5/납품을 차단한다. target LUFS/tolerance/max dBTP는 프로젝트 입력이지 보편 -14 preset이 아니다. 측정값은 정확한 artifact pin과 QA report에 남기며 자동 gain 변경을 하지 않는다. main/clean 같은 같은 규격 branch는 별도의 실제 native 출력/QA/계보를 bundle에 포함하고 editable은 두 branch producer union을 실제 relink/reopen한다. 가로→9:16 reframe은 이 경로의 지원 인증이 아니다.

실제 출력의 container/video/audio codec/sample rate/channels를 독립 probe하여 profile과 대조한다. 초기 native export는 MP4/H264/stereo AAC이며 FLAC 등 미지원 선언은 준비·raw packet 실행 전에 거절한다. 공급된 style.attribution은 실제 main/variant producer union에서 수집해 records/attribution.json에 style/license/reference pins와 함께 보존한다. attribution_presentation은 receiver_record가 기본이며 명시 on_screen은 검증된 실제 표시 경로 없이는 PG6/채택·납품을 모두 차단한다. 이 기록은 법적 발급자 진위 인증이나 자동 크레딧 burn-in이 아니다.

master-only와 editable은 다른 계약이다. editable은 실제 source/native inventory·상대 relink·receiver font 또는 허용 재배포·원본/relocated hash와 세 앱 실제 reopen을 검증한다. 필수 stem/variant/native/권리/font를 MP4 하나로 대체하지 않는다. 개인 절대경로/credentials·원본 template/font를 자동 공개하지 않는다.

## 검증과 명시 미완료
```bash
python3 scripts/check_package.py --json
python3 scripts/check_acceptance.py --snapshot > qa/implementation/current-test-scope.json
python3 -m pytest -q --junitxml=qa/implementation/current-test-results.xml
basedpyright postproduction
python3 scripts/check_acceptance.py --json
```

각 실행의 stdout/JUnit/scope는 버전별로 별도 보존한다. source/spec/schema/acceptance map/역할·운영 문서 변경 후 예전 scope를 새 run으로 가장하지 않는다. `check_acceptance`의 qualified automated trace는 각 P ID에 실제 실행 PASS node가 있는지 검사한다. **52개의 완전한 실영상·설치 시나리오 성공이나 E4 인증을 뜻하지 않는다.** 행별 `unverified`를 반드시 읽는다. P06/P11/P14/P18/P22/P33/P34의 실제 혼합clock/VFR 거절·세 앱 prepare purity·injected offline/warning·native 중간 실패·원장 rename/second-write 장애·EBU R128/true-peak·conditional master-consumption 보강을 수행했다. native 렌더/관측과 주입한 장애·보고된 의미 fixture는 구별한다. 실제 인간 지각/신규 vendor 설치를 추적으로 완료 집계하지 않는다.

현재 whole-suite 증거는 `qa/implementation/`의 실제 checkpoint를 따른다. 추가 개발 중에는 이전 full suite와 최신 targeted 결과를 구분한다. Ruff는 발견하지 못해 설치하지 않았으며 lint PASS를 주장하지 않는다. 에이전트 role pressure/compliance의 반복 fresh-context 대조 시험은 수행하지 않았다. Package checker는 machine-consumed frontmatter/실제 링크/schema만 검사하며 한국어 지시 문장의 단어 순서를 행동 검증으로 세지 않는다. 설치 질문·동의는 실제 CLI/library의 side-effect denial 검사로 집행하고 역할 지시 해석은 최종 독립 검수 범위다. 승인된 새 최종 read-only reviewer는 전체 scope freeze 이후 한 명만 사용한다.
