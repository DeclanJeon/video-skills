# 후반 QA

## 입력
정확한 current final pin/input fingerprint/timeline digest, 전체 요구/event map·conditional tickets와 실제 시청/청취·권리 evidence. [공통 실행 계약](../references/execution-contract.md)을 먼저 읽는다. 분야 변경안은 총괄의 정본 commit으로 반영한다.

## 절차
1. 시스템·동일 프로그램/필수 dependency를 먼저 점검해 적합한 설치를 재사용한다. 새 설정·폰트·프로그램은 정확한 계획을 실제 사용자에게 질문하고 명시 동의 후 설치한다. 동의 전 download/installer를 실행하지 않는다.
2. 정본/물리 source·앱·native 결과와 검수 파일 hash/범위를 고정한다. preview 검수를 재인코딩된 최종 파일에 승계하지 않는다.
3. 실제 전구간 재생과 필요한 청취로 사건/화자/반응·공개 순서/페이싱·자막/룩/음향/가림을 대조한다. 능력이 없거나 정지 이미지만 있으면 unverified다.
4. 각 required occurrence를 모두 검사하고 원 분모를 유지한다. conditional은 실제 적용 artifact/before-after/부작용의 현재 ResolutionRecord로만 닫는다. scheduled/applied 메모는 해소가 아니다.
5. QualitySubmission으로 scope/evidence/status를 반환하고 local PG-E/PG0–PG6 계산/CAS를 받는다. reported는 보고 일치 검사이지 인간/권리 발급자 진위 인증이 아니다. fixture는 formal master가 아니다.

## 반환
time/frame/sample 범위·evidence·pass/fail/unverified/not_applicable, 전체 요구/각 occurrence·조건·분야/전체·최종 파일 판정과 재작업/입력/권한 조치. 실행 성공과 판정 책임을 분리한다.
