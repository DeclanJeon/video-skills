## 1. 한 문장 목표

**영상 = 종합 엔터테인먼트**라는 관점으로, 감독(오케스트레이터)이 팀원(스킬)들을 부서별로 호출·조율해
`기획 → 수요·반응 검수 → 에셋 설계 → 콘티 → 스토리보드 → 프리프로덕션 검수 → 스토리보드 시트(이미지) → 영상 프롬프트 → 제작`
을 끊김 없이 진행하고, **모든 산출물이 하나의 인덱스로 서로를 가리키게** 만든다.

## 3. v1 진단 — 무엇이 허점인가

## 4. 설계 원칙

1. **감독은 비전을 주고 시킨다.** `production-director`는 콜시트를 발행하고, 납품을 받고, 게이트를 소집하고, 충돌을 판정하고, 원장에 기록한다. 감독이 직접 쓰는 창작물은 장면별 **연출 노트(`DNT`)** 하나뿐이고, 나머지는 크루가 만든다.
2. **한 부서 한 산출물.** 각 크루는 정해진 산출물 문서(아티팩트) 하나 이상을 소유한다. 같은 사실은 한 문서에만 쓰고 나머지는 ID로 가리킨다(단일 정본).
3. **인덱스가 척추다.** 모든 산출물·하위 항목에 ID가 있고, 스토리보드 시트는 컷마다 그 컷에 관여하는 모든 ID를 가리킨다. 프롬프트는 ID를 **풀어서** 쓰되(모델은 ID를 모른다) 별도 출처 사이드카로 역추적 가능해야 한다.
4. **수요 먼저, 모방은 구조만.** 성공한 비교 사례에서 구조(훅 위치, 비트 간격, 감정 곡선, 반전 시점)를 빌리고 표현(대사, 캐릭터, 고유 장면)은 빌리지 않는다.
5. **검수는 게이트, 게이트는 판정.** 각 QA는 `PASS / REVISE / RETHINK` 중 하나를 내고, 수정 지시는 ID로 색인한다. 최대 2회, 2회차는 영향 범위만 검사한다.
6. **텍스트는 공짜, 실행은 승인.** 텍스트 단계는 자동 진행, 이미지·영상·음성의 유료/외부 실행은 승인이 있어야 한다(v1 정책 승계).
7. **모델 중립, 방언은 직렬화에서.** 프롬프트 내용은 모델 중립 슬롯으로 설계하고, 선택된 모델의 언어·길이·문법은 마지막 직렬화 단계에서만 적용한다.

## 6. 범위

**범위 안**: 크루 20개 스킬 정의, 단계·게이트, 아티팩트·ID·인덱스 규약, 1차 QA 방법론, 콘티 회의 규약, 이미지/영상 프롬프트 규격, 검사 스크립트 3종(`index_lint`, `prompt_lint`, `timeline_check`) 명세, v1 이관, 평가 시나리오.

**범위 밖(이번 설계)**: 공급자 어댑터 재작성(v1 것을 그대로 연결), 포스트프로덕션 심화(편집·믹스·색보정은 `film-editor`·`sound-designer`의 후반 레인으로 최소 정의), 게시·배포 자동화, 성과 분석 자동화.

## 7. 가정과 위험

| ID | 가정/위험 | 처리 |
|---|---|---|
| A1 | 사용자는 승인 대기 없이 설계 전 과정을 진행하길 원한다 | 질문 대신 결정 로그에 기록. 이견은 리뷰에서 수정 |
| A2 | 대상 하네스: Pi/Codex/Claude Code (SKILL.md 포맷 공통) | 하네스 전용 도구 이름을 스킬 본문에 쓰지 않는다 |
| A3 | 기본 출력 언어는 한국어, 프롬프트 언어는 모델 방언에 따름 | [07 §5](07-video-prompt-spec.md#5-모델-방언과-언어) |
| R1 | 스킬 20개 description이 항상 컨텍스트에 실린다 | 크루 description ≤40단어, WO-01에서 총 토큰 실측, 2,500토큰 초과 시 D1 재검토(크루를 감독 내부 참조로 강등) |
| R2 | 가상 시청자 패널이 "예측"처럼 오용될 위험 | 숫자 예측 금지, `hypothesis` 라벨 강제, 벤치마크 관측과 합산 금지 |
| R3 | 콘티 회의 라운드가 길어져 토큰·시간 비용 증가 | 부서별 "해당 없음" 즉시 반환 허용, 단편(≤60초)은 경량 회의 모드 |
| R4 | 모방이 표절로 넘어갈 위험 | 차용 원장에서 표현 차용 금지, 거리 검사(§04-2) |
| R5 | 모델이 프롬프트 속 ID 문자열을 화면 글자로 렌더 | 프롬프트 본문 ID 금지(`prompt_lint` L8), 출처는 사이드카 |
| R6 | 서브에이전트 실행(독립 QA·병렬 부서) 시 토큰·시간 비용 증가 | 서브에이전트는 QA 게이트와 병렬 디자인 부서에만 우선 적용([01 §9](01-pipeline-and-gates.md#9-실행-메커니즘)), WO-13에서 인라인 대비 비용 측정 |
