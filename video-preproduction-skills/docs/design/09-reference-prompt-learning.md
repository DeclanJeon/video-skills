## 1. 원칙 — 구조와 패턴만 가져온다

레퍼런스 프롬프트는 **어떻게 쓰는지**를 배우는 교재다. **무엇을 찍는지**(이야기·인물·대사·배경)는 가져오지 않는다. [DES-04의 차용 원장](04-qa1-audience-reaction.md#22-차용-원장-bor)이 각본에서 "구조는 빌리고 표현은 빌리지 않는다"를 적용하듯, 이 문서는 같은 원칙을 프롬프트 작성법에 적용한다.

| 가져온다 (구조·패턴) | 가져오지 않는다 (내용) |
|---|---|
| 블록 순서와 각 블록이 맡는 역할 | 줄거리·전제·갈등 소재 ("누가 무엇으로 다투는가") |
| 문장 짜임새 (예: "이것은 X가 아니라 Y다") | 인물 설정 (나이·인종·직업·외모·의상의 구체값) |
| 시간을 나누는 방식 (샷 머리 절대 시간, 긴 테이크의 하위 구간) | 대사 문장, 인물 이름 |
| 표정 서술법 (부위별 관찰 서술 + AU 보조 + 감정의 목적) | 시대·장소·소품·팔레트의 구체값 |
| 대사 전달 지시법 (속도·질감·강세 단어·쉼) | 특정 감정 곡선의 단계 이름 그 자체 |
| 사운드·금지 블록을 묶는 방식 | 원문 문장의 번역·의역 |
| 실패를 막는 장치 (드리프트 잠금, 실존 인물 모방 금지) | — |

판단이 애매하면 **바꿔 넣기 시험**을 한다. 그 요소를 전혀 다른 장르·시대·인물의 영상에 그대로 옮겨 써도 말이 되면 구조고, 말이 안 되면 내용이다. 예: "긴 테이크를 감정 단계별 하위 구간으로 나눈다"는 어디에나 쓸 수 있으므로 구조다. 인물이 무언가를 견딘 *햇수 같은 고유 숫자*나 그 인물의 직업·관계는 이 이야기에만 맞으므로 내용이다.

## 2. 배울 것 — 패턴 카탈로그

각 패턴은 내용과 상관없이 정의한다. "반영"은 v2에서 그 패턴을 강제하는 위치다. 상태는 아직 `observed-in-reference`(레퍼런스에서 관찰됨)이며 실제 생성으로 효과를 검증하지 않았다(§6).

### 2.1 전체 설정

| ID | 패턴 | 왜 효과적인가 | v2 반영 |
|---|---|---|---|
| PP-01 | **첫 문장 = 사양 요약**: 길이·사실감 수준·오디오 방식·장르를 한 문장에 | 모델이 가장 먼저 읽는 문장이 생성 전체의 모드를 정한다 | B1 1문장째 필수 |
| PP-02 | **룩 한 단락**: 화면비 → 촬영 질감(fps 체감·그레인) → 시대·장소 → 장소 핵심 요소 3–4개 → 빛(시간대·방향·색온도) → 팔레트 → 피할 장르감 | 기술 사양과 분위기를 한 덩어리로 묶어 샷마다 반복하지 않는다 | B1 순서 고정 |
| PP-03 | **부정 정의로 연기 양식 고정**: "이것은 <피할 양식>이 아니라 <원하는 본질>이다" | 모델이 기본으로 가는 과장 연기를 이름 붙여 막고, 대신 갈 방향을 준다 | B2 1문장째, 출처 `DNT#tone` |
| PP-04 | **카메라 절제 선언**: 감정을 운반하는 수단(얼굴·호흡·시선·목소리)을 명시하고 카메라는 조용히 | 카메라가 감정을 대신 연기하려는 경향을 막는다 | B2 2문장째, 출처 `DNT#camera` |

## 4. 프롬프트 패턴 원장 (`PPL`) — 다음 레퍼런스부터의 학습 절차

이번 레퍼런스만이 아니라 앞으로 들어오는 좋은 프롬프트에도 같은 절차를 쓴다. `video-prompt-engineer`(이미지면 `image-prompt-engineer`)가 소유하고, 패키지 수준 산출물로 `video-prompt-engineer/references/pattern-ledger.md`에 누적한다(프로젝트 산출물이 아님).

1. **원문 보관.** `docs/examples/<ref-id>/source-*`에만 둔다. 출처·받은 날짜·권리 메모를 머리에 쓴다. *완료 기준: 원문 파일 1개, 머리말 3항목.*
2. **내용 제거 골격 만들기.** 인물·장소·소품·대사·고유 수치를 자리표시자로 바꾼다(`<인물 A 외형>`, `<대사 n: 영어 18단어>`). 문장 짜임새·순서·시간 숫자·카메라 수치는 남긴다. *완료 기준: 골격 안에 §5 누출 단어 0개.*
3. **패턴 추출.** 골격에서 패턴을 뽑아 카탈로그(§2)와 대조한다. 판정은 `기존`(이미 있음)·`변형`(기존 패턴의 다른 형태)·`신규`. *완료 기준: 골격의 모든 단락이 하나 이상의 PP-ID에 매핑됨.*
4. **결함 찾기.** 골격에 `prompt_lint`를 돌리고, 결함을 SUP-ID로 일반화한다. *완료 기준: lint 결과 첨부, 결함마다 SUP-ID.*
5. **채택 결정.** `신규` 패턴은 바꿔 넣기 시험(§1)을 통과해야 카탈로그에 들어간다. 템플릿·lint·담당 부서 중 어디에 넣을지 정한다.
6. **검증 상태 기록.** 처음에는 `observed-in-reference`. §6의 비교를 거치면 `validated` 또는 `rejected`.

원장 행 형식:

```markdown
| PP-ID | 패턴(내용 없음) | 출처 ref-id·단락 | 판정 | 반영 위치 | 상태 |
| PP-10 | 긴 테이크를 감정 단계별 하위 구간으로 나눈다 | REF-PROMPT-01 ¶샷2 | 신규 | B5, CNT .bn | observed-in-reference |
```

## 6. 패턴 효과 검증 (구현 이후)

패턴은 레퍼런스에서 **관찰**된 것이지 효과가 **검증**된 것이 아니다. 효과 검증은 실제 생성이 필요하므로 `AP-VID` 승인 안에서만 한다.

- 방법: 같은 합성 장면(EX-02)으로 "패턴 적용 프롬프트"와 "패턴 하나를 뺀 프롬프트"를 같은 모델·같은 설정으로 생성해 QA5 항목(표정 비트 시점, 립싱크, 드리프트, 금지 위반)으로 비교한다.
- 우선 검증할 패턴: PP-10(감정 사다리), PP-12(AU 보조), PP-14(대사 3종 세트), SUP-15(금지 목록 균형) — 비용이 크거나 효과 논란이 있는 것부터.
- 승인 뒤 `scripts/ab_blind.py`로 패턴별 최소 3쌍을 배정한다. 채점자는 라벨만 받고 배정표는 채점이 잠긴 뒤 연다. 생성 실패·결측은 사유를 남기고 일부 쌍만으로 채택하지 않는다.
- 채택 신호가 나오더라도 해당 장면·설정의 탐색 결과로만 기록한다. 다른 합성 장면 또는 모델에서 재현하고 저하 항목을 확인하기 전까지 원장 상태를 `validated`로 올리지 않는다. 효과가 없는 패턴은 강제하지 않는다.
