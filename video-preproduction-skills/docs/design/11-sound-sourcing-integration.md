# 11 — 프리프로덕션 사운드 소스 통합 계약

- 문서 ID: DES-11 · 상태: 통합 구현 반영, 검증 범위는 §6
- 범위: 감독·단계표·QA·등록·콘티·역할 간 연결. 사이트 탐색/다운로드/청취 절차의 단일 정본은 [스톡 사운드 계약](../../sound-designer/references/stock-audio-sourcing.md)이다. 이 문서는 이를 다시 구현하지 않는다.
- 사용자 승인 목표: video-skills/.ultragoal/goals/active/preproduction-sound-integration/goal.md. 100%는 스킬 통합과 검증이며 실제 작품의 음원 확보를 뜻하지 않는다.

## 1. 선택과 요구 추적

새 음원 크롤러/병렬 큐 원장은 만들지 않는다. 기존 SND·AMB/SFX/MUS·CNT·index.csv·ledger·QAR에 연결하는 방식을 선택한다. 역할 파일만 수정하면 감독의 단계표/QA가 옛 완료 기준을 따르는 문제가 남고, 새 파이프라인은 기존 핀/변경 전파와 분리되므로 둘 다 배제한다.

| 요구 | 책임/소비 지점 | 검사 |
|---|---|---|
| 감독의 배정·요청 종료점 | production-director, DES-01 | 소스 포함/텍스트-only/무음/부분 차단 사례 |
| 시점별 설계와 확보 구분 | P2/P3/QA2/P6/QA4/프리 납품 | §2 표와 사례 대조 |
| 근거 없는 소스 ready 차단 | production-qa, DES-03 | 누락 파일·해시·청취·권리·Content ID·재배포 사례 |
| 소스/증빙/큐시트 등록 | production-ledger, DES-03 | 기존 Ledger/index_lint를 실제 호출하는 회귀 |
| 실측 길이·편집 사용 구간 | assistant-director, CNT/부서 레이어, SND | 길이 변경·루프·J/L-cut 영향 사례 |
| 새 역할 경계 | DES-02, sound-designer | 스톡 검색/확보는 음향, 생성은 승인된 실행자, 최종 편집은 포스트 |
| 안전한 재개·수정 | 기존 writer/consumes, 오케스트레이터 인계 | source/rights/review 버전 변경의 실제 stale 전파 |

## 2. 범위와 단계별 배정

SND에 요청 범위(설계/텍스트-only 또는 실제 소스 확보), required 여부와 근거, 사용 목적을 기록한다. 용도는 `generation_input`(해당 영상 생성 요청이 실제 소비), `post_only`(편집 시 배치), `design_only`(설계 지시만)로 구분한다. 이는 보드에 새 필수 열을 만들지 않고 SND/사운드 레이어/소스 원장에 둔다. 모델이 native 오디오를 지원해도 스톡의 업로드/컨디셔닝 권한과 실제 모드 지원을 별도로 확인한다.

| 시점 | 감독 배정과 완료 조건 | 아직 미확보일 때 |
|---|---|---|
| P2 | sound-designer가 큐 기능·금지·무음·용도·required/요청 범위를 설계하고 관련 자료처 탐색 시작 | 후보/미탐색/미확인으로 표시. 이미지 작업 등 독립 작업 진행 가능 |
| P3 | sound-designer와 assistant-director가 컷별 작품 구간·소스 후보 길이/실측 여부·필요 source in/out·루프/J/L 의도를 합의 | 추정과 실제를 구분. 필요한 시간 근거가 없는 영향 컷만 보류/대안 제시 |
| QA2 | sound design의 빠진 필수 큐·무음 근거·용도·시간 배정·탐색/확보 상태를 검수 | 설계 판정과 실제 확보 판정을 분리. 설계 PASS가 파일 확보 PASS 아님 |
| P5/QA3 | 이미지·시트 관련 계약 유지 | 무관한 post_only BGM 미확보로 시각 작업을 막지 않음 |
| P6/QA4 | 실제 생성 요청에 쓰는 generation_input 오디오의 현재 파일·핀·청취·권리·모드/선택 ref/승인 확인 | 해당 제출만 차단. post_only를 억지 업로드하거나 native 음향 입력이라고 가정하지 않음 |
| 요청한 프리 납품/프로·포스트 인계 | 범위에 실제 소스 확보가 포함되면 required인 모든 큐의 현재 파일·기술 검사·최종 파일 청취·개별 권리/크레딧·전달 조건과 큐시트 검수 | director는 설계 완료와 확보 partial/blocked를 함께 보고; 필수 소스가 없는데 전체 프리 납품 완료라고 하지 않음 |

이 표의 마지막 줄은 새 파이프라인/새 gate ID가 아니라 요청 종료점의 기존 납품 체크다. DLV의 기존 self_verdict는 complete/partial을 유지하며 blocked 사유는 missing_inputs/assumptions와 감독 응답에 기록한다. 새 enum이나 원장 상태를 만들지 않는다. production-qa가 현재 범위에 맞는 기존 QAR에 증거를 추가하고 감독이 DLV를 판정한다. 전체 경로 P6 인계에는 QAR-4, P2/P3의 직접 사운드 납품은 해당 범위의 QAR-2를 사용한다. 직접 호출의 tmp 규약과 원장 없는 범위는 기존 DES-01/감독 규칙을 따른다.

소스의 미확보·미청취·불명확한 권리/전달 범위는 **소스를 실제 사용하는 제출과 확보 포함 납품**의 차단 사항이다. 2회 QA 상한 뒤 residual_risk로 바꾸어 준비 완료로 넘기지 않는다. 이미 승인된 무료 다운로드 범위는 반복 승인하지 않고, 새로운 비용·계정·약관·전송은 기존 권한 경계를 지킨다. 읽기/청취 도구가 없으면 실제 부족 기능과 재개점을 기록한다.

## 3. 파일과 증빙을 기존 ID/원장에 등록

새 접두사/핀 문법/원장은 도입하지 않는다. 작품 프로젝트의 기존 폴더 안에 원본 파일·원장 사본·증빙을 저장하고 공유 스킬에는 두지 않는다.

| 기존 ID | 등록 대상과 consumes |
|---|---|
| AMB-nn / SFX-nn / MUS-nn | 설계 단계에는 해당 큐 계획 문서. 확보 후 다음 버전은 실제 선택 미디어 파일(예: MUS-01@v2); 개별 권리 증빙 REF 버전을 소비 |
| REF-* | 기존 가변 tail 문법의 참조 파일을 재사용: REF-MUS-01-rights는 항목별 약관/인증서/크레딧/범위 증빙, REF-MUS-01-review는 정확한 미디어 핀·SHA와 기술/실제 청취 관측을 기록하고 그 MUS 버전을 소비 |
| REF-SOUND-SOURCES / REF-SOUND-SEARCH | 기존 소스 원장 CSV / 검색 기록 CSV를 등록. 소스 원장은 선택된 큐 미디어·권리·리뷰 버전들을 소비. 검색 기록은 탐색 관측이며 권리 승인 아님 |
| SND | 현재 큐/소스 원장·권리·리뷰 핀을 소비하고 요청한 설계/확보 완료를 별도 기록 |
| CNT → STB → VPR / QAR | 실제 사용한 SND/큐/사운드 레이어 버전만 소비. QAR은 검수 대상 핀과 증거를 소비하며 미디어가 자신을 검수한 QAR/리뷰를 역으로 소비하지 않음 |

REF의 확장은 이미 파서가 받는 참조 파일 용도이며 이미지가 아닌 파일을 이미지 기준으로 자동 전송/검수하라는 뜻이 아니다. 바이너리 MUS/AMB/SFX에 Markdown anchor를 붙이지 않는다. 컷별 source 구간/용도는 SND/CNT와 소스 원장의 cue 행에 연결한다. 같은 파일을 여러 큐가 쓰면 같은 원본 path/hash를 가리킬 수 있지만 큐별 사용 구간은 구별한다.

등록 순서는 rights REF → 미디어 AMB/SFX/MUS → review REF → 소스 원장 REF → SND → 실제 소비 CNT/STB/VPR/QAR다. 권리 버전 변경으로 기존 미디어가 stale이면 바이트가 같아도 새 권리 핀을 소비하는 미디어 다음 버전을 먼저 등록하고, 그 현재 미디어를 소비하는 리뷰 다음 버전을 등록한다. 리뷰 버전 변경은 원장/SND/소비자만 stale로 만들며 미디어가 리뷰를 역소비하지 않는다. review는 관측 보고서이지 프로그램이 청취 진실/법적 허가를 인증하는 서명이 아니다. 이 순서로 cycle을 피하고 미디어/권리 변경 시 현재 리뷰/사용자들이 stale이 된다. 단순 계획 ID가 current로 등록되어 있다는 사실은 실제 파일 확보가 아니다.

**기계 검사의 범위:** index_lint는 보드에서 직접 참조한 현재 큐 파일의 존재·해시·버전/상태를 검사한다. 모든 consumes 파일을 재귀적으로 검증하거나 권리/청취의 진실을 인증하지 않는다. production-qa는 소스 원장의 각 핀 및 증빙/리뷰의 현재 바이트를 원장과 대조해야 한다. 실제 재생/청취와 intended use 권리 판정은 별도 판단 검사다. 새로 만든 CSV 양식 자체는 runtime gate가 아니다.

감독만 production-ledger 절차로 등록/상태를 기록한다. combined ledger namespace 손실을 막는 기존 오케스트레이터 writer 격리 계약을 유지한다. 파일을 덮어쓰지 않고 새 버전 path로 남기며 원장 등록은 권리 승인/확보 완료가 아니다.

## 4. 큐 길이·소스 변경의 영향

사운드 레이어의 각 큐에는 `cue_ref`, `use_stage`, `required`, `timeline_in_s/out_s`, `source_in_s/out_s`, `measured_duration_s` 또는 추정/미확인 상태, `loop_region_s`/반복 허용 근거, 대사/ducking/J/L 의도, 현재 소스 원장·리뷰 핀을 둔다. 기존 layers.sound.cues 슬롯 안에서 표현하며 기존 index의 ambience/sfx/music에는 기존 큐 버전 핀을 쓴다.

소스가 짧거나 바뀌었다고 조연출이 실제 stretch/loop/trim을 적용한 것으로 기록하지 않는다. source_out이 실제 길이를 넘거나 필요한 루프/재사용 허가가 없으면 영향 큐/구간을 보류하고 (1) 적합한 다른 소스 (2) 승인 가능한 구간/리듬 변경을 감독에게 제안한다. 원문 대사나 전체 러닝타임을 임의로 바꾸지 않는다.

- 미디어·권리·리뷰/원장 버전 변경: 기존 consumes의 stale 전파 및 관련 보드 index_lint를 실행하고 바뀐 파일/구간을 다시 검수한다.
- 실제 대사/컨디셔닝 타이밍이 바뀌면 assistant-director는 자기 소유의 CNT·컷/발화 구간만 보정하고 영향 큐/대사를 감독에게 보고한다. 감독이 APR은 sound-designer, VPR/사이드카/GEN 배치는 video-prompt-engineer에게 재배정한 뒤 timeline_check·관련 prompt/batch 검사·QA4를 재실행한다. 조연출은 다른 부서의 APR/VPR을 직접 쓰지 않는다.
- post_only BGM 교체가 영상/이미지 의미·타이밍을 바꾸지 않으면 음향 사용·권리·인계만 다시 본다. 해당 이미지를 자동 재생성하지 않는다. 기존 그래프가 넓게 stale을 전파하면 필요한 현재 핀을 다시 등록/검수하되, 바이트/의미가 유지된 이미지를 '새로 생성했다'고 하지 않는다.
- 프로가 이미 시작됐다면 오케스트레이터가 scope/invalidate/revalidate를 판단한다. 초기화로 원격 job/unknown 기록을 지우지 않는다.

## 5. QA 판정 계약

QA2는 큐 설계/상태의 완결성, QA4는 해당 generation_input의 실제 준비와 모델 입력 계약, 요청 종료점 납품은 required 소스 전체의 준비와 수령 범위를 본다. 표와 상태를 함께 보고 현재 보드 구조 검사만으로 세 가지를 통과시키지 않는다.

실제 소스 준비의 필수 근거는 (a) 정확한 현재 미디어 파일/해시 (b) 기술 검사와 실제 길이 (c) 최종 파일의 실제 청취 구간/방법/관측 (d) 항목별 라이선스/용도/크레딧/필요한 Content ID 대응 (e) 큐별 작품/소스 구간과 수령자 원본 전달 허가다. 하나라도 필요한데 미확인이면 관련 확보/사용을 미통과시킨다. 의도된 무음/텍스트-only는 해당 소스 의무가 없음을 명시하고 실제 확보 완료라고 바꾸지 않는다.

현재 프로그램은 이 모든 판단을 자동 집행하지 않는다. 기계 증거와 판단 근거의 슬롯·책임·납품 차단을 연결하는 스킬 계약이며 테스트는 실제 동작하는 파일/원장/인덱스 seam만 검사한다.

## 6. 검증·구현 추적

- 회귀: tests/test_sound_sourcing_contracts.py. 기존 Ledger/index_lint에 실제 사운드 큐 파일·권리/리뷰 refs·consumes 그래프를 넣어 current/누락·바이트 변화/stale을 관측한다. 자연어 문장 일치 테스트는 사용하지 않는다.
- 사례 QA: 소스 포함/텍스트-only/무음/필수 파일 누락/미청취/권리 불명/Content ID/재배포/길이 교체/후반 전용과 컨디셔닝/포스트 미준비. 결과는 해당 goal evidence에 기록하고 실제 웹/미디어 작업과 구분한다.
- 전체 검사: pytest, check_skills, doc_check, consistency_check, 실제 read 도구의 6개 등록 catalog 접근.
- 독립 최종 검증: goal R1–R8, 현재 파일 해시, 실행 로그와 실제 변경 범위를 fresh-context reviewer가 읽기 전용으로 확인한다. 유료 사이트 접근·실제 오디오 청취·다운로드·포스트 구현은 이 목표에서 미수행이다.
