# DES-13 — 실행 안전 계약

적용: 영상 설계·생성·재생성·연속 제작·최종 납품. 해당 단계에 필요한 결정과 근거만 기존 브리프·콘티·인계 기록에 남긴다. [실행 명세 양식](../../production-director/assets/execution-safety-template.json)은 흩어진 근거를 묶어 인계할 때만 사용한다. 새 공급자/모델/매체 호출 권한을 부여하는 계약은 아니다.

## 0. 최소 설계 — 기존 단계에서 세 가지 질문
1. **브리프:** 어떤 해석 차이가 화면·소리·납품을 바꾸는가? 확정된 요구는 재질문하지 않는다. 미정이고 결과를 바꾸는 결정만 확인한다.
2. **콘티:** 관객이 이 컷에서 무엇을 알아야 하고, 직전 상태에서 그 행동이나 변화가 성립하는가? 위치·소품뿐 아니라 신체 능력, 감정, 가시성을 해당 컷에서 확인한다. 별도 상태표는 기본값이 아니다.
3. **인계:** 어떤 구현 방식이 아직 불확실하고, 틀리면 영향 범위가 큰가? 해당 구간만 가장 싼 근거로 확인한다. 판정 근거는 기존 문서 한 줄로 충분하다.

기존 산출물로 판단 가능하면 추가 산출물을 만들지 않는다. 승인·권리·비용 및 최종 검수 조건은 그대로 적용한다.

## 1. 스타일 잠금 — 생성 전
- `visual_style`(실사/애니/기타)와 `voice_direction`(성우 연기·발성·감정)을 별도로 기록한다. 각각 사용자 발언 또는 승인된 브리프 핀을 붙인다.
- “톤”처럼 시각·음성 해석이 갈리고 결과가 달라지면 해당 변경만 보류하고 범위를 확인한다. 시각 스타일의 공용 기본값은 없다. 대사가 없는 작품의 음성 연기 방향은 해당 없음으로 처리한다.
- 확정된 시각 스타일과 모든 실제 입력 이미지·프롬프트를 대조한다. 스타일 변경 시 영향 참조·패널·VPR은 재검토 대상이다. 확인 전 전체 재생성하지 않는다.

## 2. 컷별 상태와 입력 범위 — QA3/QA4
변신·봉인·의상 교체는 요소별 `first_allowed_cut`과 상태 종료 컷을 기록한다. 각 GEN은 보이는 인물·소품·의상 단계에 필요한 `allowed_reference_ids`만 보낸다.
- 변신 전 얼굴은 일상복 참조를 사용한다. 미래 완성복·날개·봉인 결과물은 해당 단계에 도달한 GEN부터 연결한다.
- 소품 보드에 미래 결과물까지 함께 있으면 필요한 소품만 크롭/분리하고 실제 바이트와 역할을 기록한다. 부정문만 추가하고 같은 혼합 보드를 그대로 보내는 것으로 해결했다고 하지 않는다.
- 프로젝트 전체 인원/무기 설명 대신 해당 GEN의 인원·도구만 기술한다. 화면 밖 인물의 존재는 CTY에 유지하되 프롬프트의 등장인물로 만들지 않는다.
- QA5에서 허용 전 요소가 등장하면 해당 테이크는 REVISE. 린트 통과나 파일 생성 성공으로 덮지 않는다.

## 3. 원본 대응 — 계획과 실제 재현 분리
“원본 그대로” 또는 특정 레퍼런스의 충실도가 납품 조건이면 **해당 구간만** 기존 콘티에 대응을 남긴다: `reference_cut`, 원본 구간, 작품 컷, 계획 길이, 고정할 구도·동작·전환, 승인된 치환, 실제 생성물의 `observed_interval`, 차이, 판정. 단순 분위기 참조에는 컷별 대응을 요구하지 않는다.
- 콘티로 구도 차이를 판단하기 어렵다면 해당 컷만 원본 프레임과 나란히 본다. 스틸과 컷 길이로 리듬을 판단할 수 없는 구간만 임시 편집한다. 전체 비교 시트나 애니매틱은 기본 산출물이 아니다.
- 컷 병합·누락·시간 압축은 명시적 변경이다. 합의 없이 원본 복제라고 표시하지 않는다.
- 텍스트 대응 PASS와 실제 영상 재현 PASS를 별도로 기록한다. 스틸만 봤으면 이동·속도·전환은 미검증이다.
- 원본 컷 길이의 근거가 추정/검출 후보인지 직접 확인인지 표시한다. 원본 복제 모드의 속도 기준은 해당 레퍼런스 실측값과 승인된 오차를 사용한다. 통과시키려고 전역 린트 기준을 완화하지 않는다.

## 4. 오디오 실행 계약 — 제출 전/QA5
`audio_policy`와 `dialogue_source`(native/post/none), 효과음·음악 경로, 후반 담당·파일·승인·재개점을 기록한다.
- 대사가 있는데 `no_audio`이면 별도 음성 제작 계획이 확정되어야 제출 가능하다. 최종 납품 전에는 계획이 아니라 실제 음성과 믹스가 필요하다.
- native 선택은 현재 공급자 스키마를 확인하고 실제 요청 필드에 반영한다. 텍스트의 “소리 포함”만으로 활성화를 추정하지 않는다.
- 검사 순서: 오디오 스트림 → 비무음 신호 → 대사 원문/화자/누락 → 청취·립싱크. 각 결과는 독립 판정이다.
- ASR은 후보 탐지다. “같이/가치”처럼 유사 발음이거나 문장 일부만 인식되면 일치 PASS 대신 미검증/재청취로 남긴다. 듣지 못한 세션은 듣지 못했다고 기록한다.

## 5. 시험 생성 — 전체 확장 전
기존 증거로 판단이 불확실하고 실패 시 재작업이 큰 경우 대표 위험 구간 하나를 가장 저렴한 방식으로 시험한다. 실제 영상 생성이 필요한 시험은 인계 이후 승인된 제작 단계에서 실시한다. `pilot_result`는 적용 범위·근거·판정을 기록하고, 실제 테이크가 있으면 파일과 `artifact_sha256`을 연결한다. 동일 조건의 유효한 근거나 낮은 재작업 비용으로 새 시험이 불필요하면 `not_needed`와 이유를 남긴다. 이는 시험 통과가 아니다.
- 핵심 요구가 REVISE/미검증이면 영향 있는 대량 생성을 보류한다. “최종까지 진행” 승인은 이 검수 게이트를 생략하는 승인이 아니다.
- 시험은 불확실한 요구만 겨냥한다. 대화극의 발화·립싱크, 제품 영상의 로고·형태, 무성 영상의 행동 가독성은 서로 다른 검증 대상이다. 시각 시험이 불확실한 대사 품질을 대신하지 않는다.
- 불확실성을 수용한 사용자 결정은 범위와 원문을 기록하고, 통과로 바꾸지 않고 승인된 제한으로 유지한다.

## 6. 공급자 요청·큐 관리
현재 스키마를 먼저 조회하고 요청 JSON, client ID, idempotency key를 **제출 전에** 저장한다. 응답·자식 run·미디어 결과까지 이 기록에 연결한다. 비밀 업로드 헤더는 기록/응답에서 제외한다.

| 실제 응답 | 처리 |
|---|---|
| `resource_busy` | 공급자 안내 대기 후 동일 본문·동일 키로 재요청. 새 키로 중복 생성하지 않는다. |
| `revision_conflict` | 거절 응답임을 확인하고 최신 revision으로 재구성, 공급자 계약에 따라 새 키로 1회 재시도. |
| `queue_full` | 신규 제출 중단. 기존 작업 종료 확인 후 생성되지 않은 요청만 다시 제출. |
| timeout/연결 단절 | 기존 run/키 상태를 조회해 조정. 실패나 취소 완료로 추정하지 않는다. |

세션 메시지는 직렬 제출한다. 공급자 허용 동시 수를 확인하고, 모르면 단일 시험부터 시작한다. 단순 대기 종료는 재생성 사유가 아니다. parent succeeded라도 child pending이면 생성 완료가 아니다. 장기 작업 상태는 로컬 파일에 저장해 재개하며 메모리 저장소만 믿지 않는다.

## 7. 최종 납품 — 증거가 없으면 review/
`delivery_review`는 현재 파일의 `artifact_sha256`, 전체 재생, `boundary_playback`(모든 경계 전후), `human_listening`(실제 최종 믹스), 대사/립싱크, 요구별 결과를 가진다. 각 검수는 reviewer·방법·근거·판정과 파일 해시에 묶는다.
- 스틸 컨택트 시트는 프레임 관찰 근거이지 전체 재생/연속 동작 증거가 아니다.
- 오디오가 있는 납품의 미청취, 필수 대사 누락 의심, 컷이 있는 납품의 미검수 경계가 있으면 `review/`에 납품하고 해당 제한을 보고한다. 의도적 무음이나 경계 없는 원테이크의 해당 없는 검사는 이유를 기록한다. 모두 충족된 파일만 `final/`로 승격한다. 파일명 candidate를 붙여 final/에 두는 것으로 게이트를 우회하지 않는다.
- 생성 성공·자막·음량 정규화·해상도 업스케일은 품질 통과가 아니다. 검수 후 편집했으면 새 해시로 영향 항목을 재검수한다.

## 검증 범위
문서·템플릿 회귀 검사: `python3 -m pytest tests/test_execution_safety_contract.py -q`.
이 검사는 필수 필드와 부서 연결을 검사할 뿐, 에이전트 행동·영상 품질·사람의 청취를 검증하지 않는다. 공급자 실행기 연결 및 독립 행동 시나리오 검증은 별도다.
