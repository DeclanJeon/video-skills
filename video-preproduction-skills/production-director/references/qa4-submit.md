# QA4 — 배치와 제출 승인

**입력:** 등록·검수된 보드 인덱스 및 승인본의 재생시간, 변형별 전체 GEN 매니페스트, 실제 제출할 프롬프트와 사이드카, 모델·엔드포인트 증거. 매니페스트가 다른 인덱스나 재생시간을 가리키면 실행 전에 돌려보낸다. 변형끼리 하나의 배치에 섞지 않는다.

1. 원장과 [인덱스 검사 계약](../../production-ledger/references/ledger-schema.md#단계별-인덱스-검사)에 따라 현재 산출물과 핀을 확인한다. 다음 명령은 패키지 루트에서 실행한다. $ROOT는 프로젝트 루트다.

   ```sh
   python3 scripts/index_lint.py --project "$ROOT" --stage prompt --json
   python3 scripts/prompt_batch_check.py --project "$ROOT" --manifest "$ROOT/batch.json" --json
   ```

2. 두 명령의 종료 코드와 실제 JSON을 기록한다. 배치 종료 **0**은 기계 검사 통과일 뿐이다. **1**은 차단, **2**는 입력·실행 오류, **3**은 미검증으로 기록한다. 모든 비제로 상태에서 제출 경로를 닫는다. 검수 회차를 소진하거나 AP-VID가 있어도 우회하지 않는다.
3. [QA4 체크리스트](../../docs/design/03-artifact-index.md#qa4--제출-전-프롬프트)에 따라 출처·논리·모델 제약을 대조한다. 등록된 사실의 엔드포인트와 실제 제출 엔드포인트가 같은지 확인한다. 가능한 경우 독립 검수로 넘긴다. inline이면 그 한계를 QAR에 기록한다.
4. QAR에는 검사 결과와 경고 판정, 매니페스트·인덱스·등록 기준·각 제출 텍스트/사이드카의 파일 해시, 실제 대상 모델·엔드포인트를 남긴다. **기계 검사 통과와 리뷰 PASS가 모두 있을 때만** AP-VID를 확인한다.
5. 제출 직전에 검수에 쓴 바이트·핀 및 실행 설정이 동일한지 다시 확인한다. 변경됐으면 해당 QA4 판정을 무효화하고 다시 검수한다. 동일하고 승인 범위·비용·권한이 남아 있을 때만 제출을 검토한다. 이 규약과 검증 스크립트는 공급자 호출을 수행하지 않는다.

## 로컬 재검 함수

`scripts/cp2/submission_gate.py`의 `fingerprint`에는 검수에 관여한 **전체** 프로젝트 상대경로를 전달한다. 매니페스트·인덱스·원장·핀의 실제 파일·각 프롬프트와 사이드카를 포함한다. 설정에는 실제 모델·엔드포인트와 제출 방언·변형·생성 옵션 등 바뀌면 재검수해야 하는 값을 포함한다. 자료 집합은 검수 전 확정하고 기계 검사 결과와 QAR을 같은 스냅샷에 묶는다.

권한 있는 호출자는 실제 QAR에서 `Review`를, 검증된 사용자 승인에서 `Approval`을 만든다. 승인 다이제스트는 승인받은 스냅샷, 비용 입력은 전체 예상 청구액이다. `authorize`의 차단 사유가 하나라도 있으면 제출 금지. 이 함수는 승인자의 신원이나 기록의 출처를 인증하지 않으며, 호출자가 입력 목록을 빠뜨리지 않았는지 자동 발견하지 않는다. 공급자 어댑터에 실제로 연결하는 작업은 별도다.
