## 실제 응답

**`tmp:BRF` — 기획 기준**  
한국어 세로 영상, 30초. 첫 3초에 편의점 알바생이 자기 실수가 아닌 재고 손실을 떠안을 위기임을 보여주고, 마지막에는 처음 나온 바로 그 소품으로 누명을 벗깁니다. 시청 목표는 ‘왜 이 사람이 물어내야 하지?’라는 억울함에서 ‘이래서 책임이 없구나’라는 납득으로 넘어가는 것. 짧은 직장 갈등극을 보는 한국어 시청자를 우선 가정합니다. 플랫폼·세부 시청층·정확한 화면비는 미정이고, 권리 확인 전에는 실제 상호나 전표 대신 가상의 매장과 서식을 사용합니다.

**BMK — `demand: unknown`**  
제공된 비교작이나 지표가 없고 요청대로 검색하지 않았습니다. 출처·게시일·수집일, 성과·댓글 반응, 사례의 훅·비트·편집 특성 모두 `unknown`입니다. 관측 사례가 없어 사례 ID나 중앙값은 만들지 않았습니다. 아래는 시장 관측이 아니라 이번 영상에서 검증할 구조 가설입니다.

**`tmp:BOR` — 같은 종이의 앞면은 추궁, 뒷면은 증거**  
비교작 근거가 없어 차용·변주로 기록할 요소는 없습니다. 각 구간의 고유 요소는 다음과 같습니다.

| 구간 | 장면에서 확인할 것 | 고유 요소 |
|---|---|---|
| 0–3초 · 갈등 | 점장이 ‘재고 부족’이 적힌 인수인계표의 ‘변상’ 칸을 짚으며 야간 알바생에게 내밉니다. | 오른쪽 위 모서리가 접힌 종이 한 장이 책임을 떠넘기는 도구로 등장합니다. |
| 3–21초 · 단서 | 알바생이 표에 적힌 자기 교대 시작 시각을 확인하고, 접힌 모서리 안쪽에 비치는 반품 도장을 발견합니다. | 앞면의 교대 시각과 뒷면의 반품 기록을 읽어야 책임 소재가 갈립니다. |
| 21–30초 · 해결 | 알바생이 같은 표를 뒤집습니다. 뒷면에는 같은 상품이 교대 전에 파손 반품됐다는 기록이 있습니다. 점장이 종이를 다시 돌려 ‘변상’ 표시를 지웁니다. | 처음 알바생을 몰아세운 종이가 누명을 벗기는 증거가 됩니다. |

**다음 단계**  
인수인계표 앞뒤에 들어갈 정보만 먼저 정리한 뒤, 위 구간을 30초 비트시트로 옮기세요. 검색 없이 확인할 최소 방법은 초안을 처음 보는 사람에게 소리 없이 보여주는 것입니다. 3초에 멈춰 “누가 무슨 책임을 떠안게 됐나요?”, 끝에서 “어떤 증거로 책임이 없어졌나요?”라고 물어보세요. 앞이 모호하면 ‘변상’ 표시를, 끝이 모호하면 같은 종이의 접힌 모서리와 교대 전 반품 기록을 더 잘 보이게 하세요. 이 확인은 장면의 이해도만 보는 것이며, 시장 수요는 미확인으로 남습니다.

## 도구 사용 기록

1. `find`: `**/concept-benchmark/SKILL.md` 경로를 확인했습니다.
2. `read`: `concept-benchmark/SKILL.md`를 읽었습니다.
3. `read` 병렬 호출: 스킬에 직접 연결된 `docs/design/04-qa1-audience-reaction.md`, `concept-benchmark/assets/BRF-template.md`, `concept-benchmark/assets/BMK-template.md`, `concept-benchmark/assets/BOR-template.md`, `docs/design/02-crew-roster.md`, `docs/design/03-artifact-index.md`, `production-director/assets/DLV-template.yaml`만 읽었습니다.
4. `bash`: `git diff --cached --quiet --`로 스테이징 여부 확인을 시도했습니다. 명령이 실패했고, `git rev-parse --is-inside-work-tree`로 작업 디렉터리가 Git 작업 트리가 아님을 확인했습니다. 스테이징은 하지 않았습니다.
5. `write`: 지정된 이 결과 파일만 저장했습니다. 평가 파일 열람, 외부 검색·호출, 프로젝트 파일 쓰기, 위임, 게시를 하지 않았습니다.
