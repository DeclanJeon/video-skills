## 사용자에게 보낼 답변

아니요. **P3 콘티 회의 중에는 부서가 수정할 때마다 정본 버전을 올리지 않습니다.** 작업본은 `CNT@draft` 하나로 유지하고, 부서끼리는 `CNT@draft#layers.<dept>`로 필요한 레이어를 참조합니다. 초안 변경은 하위 산출물에 `stale`을 전파하지 않으며, 초안 참조는 P3 안에서만 씁니다.

**지금 R3 조명이 볼 입력은 `CNT@draft#layers.camera`입니다.** R2 촬영 레이어가 반환됐다는 건 납품됐다는 뜻이지 승인됐다는 뜻은 아닙니다. 감독이 반환본의 컷별 카메라 정보(`CAM-nn`, 카메라 위치·방향 등)와 잠긴 각본(`SCR`), 연출 노트(`DNT`), P2 바이블의 실제 유효 버전 핀을 확인한 뒤 조명 입력으로 넘기는 순서입니다. 조명은 자기 레이어만 수정하고, 촬영과 충돌하는 부분은 촬영 레이어를 고치지 않고 납품의 `conflicts`에 올립니다. 감독이 `RUL`로 판정하고 영향받은 부서만 수정합니다.

**모든 레이어 승인 후 R7에서 첫 정본 `CNT@v1`을 한 번만 등록합니다.** 조감독이 아래를 모아 확인하고, 감독이 마감과 등록을 맡습니다.

- 모든 컷에 R0–R6 레이어가 있거나 `none(이유)`가 적혀 있음
- 컷 길이 합이 러닝타임과 같고 하위 구간이 각 컷을 빈틈없이 덮음
- 모든 대사 `D`가 컷과 하위 구간에 배정됨
- 미판정 `conflicts`가 0건이고, `CTY`의 모든 상태 전이가 컷 또는 하위 구간에 연결됨

나중에 실제 쓰기가 허용되면, 감독이 프로젝트 안에 별도 버전 파일(예: `03_conti/CNT-v1.md`)을 만든 뒤 `production-ledger`로 등록합니다. 원장에는 경로·해시와 실제로 소비한 `SCR`·`DNT`·바이블의 유효한 `@v` 핀을 `consumes`에 남깁니다. 부서 납품이나 레이어 승인 자체가 정본 등록은 아닙니다. 등록 이후 P4 스토리보드는 `CNT@v1`을 참조하며, QA2는 P4 이후 별도로 진행합니다.

대기: 요청하신 채팅 정리에서 중지 — 필요: 실제 인계·등록은 이번 요청에서 실행하지 않습니다.

## 실제 작업 로그

1. 파일 찾기로 `production-director/SKILL.md` 위치를 확인하고 읽음.
2. 라우팅된 규약만 읽음: `docs/design/05-conti-collaboration.md`(P3 의존 순서·충돌·마감), `docs/design/01-pipeline-and-gates.md`(인계·단계·정지), `production-ledger/SKILL.md`(등록 권한·절차), `docs/design/03-artifact-index.md`(초안 참조·stale), `production-ledger/references/ledger-schema.md`(첫 버전·파일·핀 등록 계약).
3. 수락 증거용 읽기 전용 Git 점검: `git diff --cached --quiet`는 종료 코드 129, `git rev-parse --is-inside-work-tree`는 종료 코드 128(작업 디렉터리에 Git 워크트리 없음). 스테이징 명령은 실행하지 않음.
4. 이 답변·로그를 요청된 세션 아티팩트에만 작성. 평가 파일이나 프로젝트 파일·원장·이력을 열지 않았음. R2 반환과 R3 대기는 사용자 진술이며, 실제 승인이나 입력 핀은 확인하지 않았음. 프로젝트 파일 쓰기, 콜시트 발행, 위임, 등록, 검사 실행, 외부 작업은 하지 않았음.
