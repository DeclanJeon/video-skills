`scripts/e2e_grade.py` and `qa/wo-13/local-scope.md`: JSON array of exactly six unique `(scenario, variant)` rows, `X-1` through `X-3` × `v1`,`v2`. Each row has `run_id` (unique), `reviewer_id` (separate from **every** executor ID), `model`, `reasoning` (nonblank strings), `brief_sha256` (lowercase 64 hex, exact brief), positive integer `input_tokens`/`output_tokens`, finite `elapsed_s`/`conti_s` with `0 ≤ conti_s ≤ elapsed_s` and `elapsed_s > 0`, plus `checks` with keys `"1"`–`"13"`, each containing integer `score` 0 or 1 and a relative `evidence` file path resolving to a nonempty file inside the root. A zero can point to a reviewer’s evidence-backed missing/failed-item note. Pair equality is enforced for model/reasoning/brief hash. Exit `0` = thresholds met, `1` = complete data below threshold, `2` = argument/input error, `3` = unverified/incomparable. The grader does **not** authenticate provenance, compare the actual bytes against the declared hash, enforce a QA4 endpoint, check the reviewer’s claims or reject a nominal zero conti duration; validate these separately. No old/pilot or partial rows.
