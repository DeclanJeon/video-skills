# 스톡 사운드 탐색·확보·인계

## 입력과 정본

[자료처 CSV](/home/declan/Documents/Projects/Products/04_Skills/Skills-and-Automation/video-skills/free_commercial_media_resources_50.csv)는 검색 출발점이다. 원본 하나를 읽고 복제 목록을 만들지 않는다. 이 링크는 정본의 절대 경로다. 등록된 패키지 별칭 위로 `../`를 넘기면 파일 도구가 symlink 해석 전에 정규화할 수 있으므로 원본 절대 경로를 사용한다. 원본이 이동했다면 실제 entry를 `readlink -f` 등 현재 지원 도구로 먼저 해결하거나, 현재 에이전트의 `<skills-root>/video-skills/free_commercial_media_resources_50.csv` 경로로 같은 원본을 읽는다. 경로가 없으면 추측한 목록 대신 원본 위치를 확인한다. BGM·OST와 SFX·효과음·폴리 범주부터 작업에 맞춰 고른다. 추천 순위는 탐색 힌트일 뿐 품질·현재 무료 여부·권리 보증이 아니다. 50개 사이트를 모두 방문하거나 라이브러리를 일괄 수집할 필요는 없다.

실제 작품의 SCR/SND, 컷·대사·시간, 요청 플랫폼·수익화·유료광고·고객사 납품 범위, 음악/소스 예산과 권한을 사용한다. 이미 정해진 값은 재질문하지 않는다. 확인되지 않은 이용 범위는 미확인으로 기록하고 필요한 권리 판정을 차단한다.

**실행 범위:** 실제 사운드 소스가 필요한 프리프로덕션이면 아래 탐색·확보를 수행한다. 사용자가 텍스트/프롬프트만 또는 다운로드 금지를 명시했으면 설계/후보 설명까지만 수행하고 실제 확보 완료와 구분한다.

## 1. 큐 브리프

기존 AMB/SFX/MUS ID마다 연결 컷·대사와 필요한 시간 구간, 기능·감정·강도·질감·거리/온오프스크린, 길이·루프·인트로/전환/끝맺음, 대사를 가리지 않을 조건·금지사항을 SND에 쓴다. 예: 긴장 BGM은 보컬/강한 타격을 피하고, 비 AMB와 문 닫힘 SFX는 별개의 큐로 비교한다. 무음이 의도이면 none(이유)이며 미확보를 무음으로 바꾸지 않는다.

## 2. 실제 사이트 순회

1. 필요한 유형(BGM, AMB, SFX)마다 관련 CSV 사이트 **서로 다른 두 곳 이상을 실제 검색**하고 후보를 비교한다. 사용자가 특정 자료처/에셋을 지정해 잠근 유형은 그 범위에서 검색한다.
2. 큐 브리프를 구체적인 한국어/영어 검색어와 길이·장르·무보컬·루프·라이선스 필터로 바꾼다. 예: “restrained tension underscore no vocals”, “steady rain exterior loop”, “wood door close soft interior”.
3. 현재 하네스에서 실제 지원되는 검색/웹 도구와 해당 스킬을 먼저 확인한다. 공개 검색 결과 → 공식 사이트 검색 → **개별 에셋 페이지**까지 따라간다. JS/로그인 사이트는 지원 브라우저로 진행한다. 없는 도구·API를 지어내지 않는다.
4. 사이트·검색어/필터·방문 시각·결과/개별 URL·후보 ID·탈락 이유·접근 차단·다음 시도를 [검색 기록](../assets/audio-search-log-template.csv)에 남긴다. 차단 사이트는 attempted/blocked이지 검색 성공이 아니다. 한 곳이 막히면 다른 관련 자료처로 이동한다. 접근제한·CAPTCHA·로그인/약관 동의는 허용된 도구/사용자 확인으로 처리하고 우회하지 않는다.
5. 의미 있는 후보가 없으면 표현·장르·동의어를 조정한 뒤 다음 관련 사이트로 넓힌다. 사이트 링크만 반환하지 않는다. 후보가 있는 큐는 가능한 2–3개를 음색·리듬/속도·길이·대사 간섭·루프/끝맺음·권리 조건으로 비교하고 선정/제외 근거를 쓴다.
6. 필요한 큐마다 청취·권리·파일 조건을 충족한 소스가 확보되면 탐색을 종료한다. 두 곳에 못 미치거나 도구/접근이 모두 막혔으면 부분 탐색과 원인·다음 사이트를 기록한다. 전체 적합 자료처를 살펴도 맞는 소스가 없으면 “적합 소스 미확보”다. 생성·유료 소스·다른 모달리티로 조용히 대체하지 않는다.

## 3. 실제 청취와 비교

공식 미리듣기 또는 허용된 실제 파일을 **실제 청취 가능한 도구/검수자**로 확인한다. 재생 버튼 클릭·파형·제목·태그·ffprobe는 청취 증거가 아니다. 들은 정확한 파일/preview URL·구간·방법·관측(대사와 경쟁하는 음역, 클릭/노이즈, 반복 경계, 거리/질감, 큐 시작/끝 적합성)을 기록한다.

미리듣기가 없으면 권리와 다운로드 조건을 먼저 확인하고 허용된 파일을 확보한 다음 듣는다. 청취 도구가 없으면 audition_status=unverified로 두고 구체적인 청취 재개 조건을 남긴다. 메타데이터만 보고 “맞는 음원 선정·청취 완료”라고 쓰지 않는다. preview와 실제 받은 파일이 다르면 최종 파일을 다시 듣는다.

## 4. 개별 에셋 권리 확인

사이트 이름이나 “free / no copyright” 문구가 아니라, **선택한 에셋 페이지·저작자·적용 라이선스 버전/약관**을 확인한다. 상업 이용·수익화·광고/고객사·플랫폼·지역/기간·편집/루프 허용·출처 문구·재배포/프로젝트 파일 납품·무료 플랜 제한을 사용 범위와 대조한다. 라이선스 이름과 URL, 확인 시각, 관련 원문/증빙 파일, 판정 범위와 미해결 조건을 기록한다.

- NC/비상업 전용은 상업 작품에서 제외. ND 등 편집 제한과 출처 조건은 실제 사용에 맞춰 해소한다.
- 공개 라이선스라도 녹음 권리와 작곡 권리 등 해당 소스의 권리 범위를 확인한다. 목록의 분류를 개별 허가로 승격하지 않는다.
- Content ID/수익화 클레임 위험, 라이선스 인증서·허용 계정/채널 등록·분쟁 증빙 요구를 별도 기록한다. 상업 이용 허용과 클레임 없음은 다른 사실이다. 불명확하면 unverified로 남기고 요구되는 인증서/화이트리스트/크레딧이 확보될 때까지 채택을 차단한다.
- 개별 조건 미확인/충돌/필수 크레딧 미확보는 rights_status=unverified 또는 blocked. 마감 때문에 cleared로 바꾸지 않는다. 필요한 라이선스 구매·로그인·개인정보 제공·새 약관 동의는 승인 범위 없으면 묻는다.

## 5. 필요한 파일만 확보

rights가 intended use에 대해 cleared이고 다운로드가 허용된 선택 후보만 공식 경로로 작품 프로젝트 내부에 받는다. 소스 확보 요청의 무료·무로그인·약관 범위 내 다운로드는 단계마다 다시 묻지 않는다. 유료·설치·계정/외부 전송 등 새로운 영향은 별도 승인한다. ZIP은 현재 승인된 도구로 안전하게 처리하고 소스/실행 파일을 자동 실행하지 않는다.

저장 시 받은 파일의 상대 경로·원본명·SHA-256·크기·형식/코덱·실제 길이·샘플레이트·채널을 확인한다. HTML 오류 페이지·preview-only·손상 파일은 downloaded/ready로 판정하지 않는다. 실제 decode 검사와 다운로드 최종본의 청취를 구분해 남긴다. 원본은 보존하고 원치 않는 변환/컷 편집은 하지 않는다. 공유 스킬 저장소에는 실제 미디어·사이트 인증정보를 넣지 않는다.

## 6. SND와 포스트 인계

[소스 원장](../assets/audio-source-manifest-template.csv)을 작품에 복사해 후보부터 기록하고 큐와 연결한다. rights_status, download_status, audition_status, selection_status를 독립적으로 기록한다. API 서명 URL·쿠키·토큰은 제거하고 안정적인 원본/라이선스 URL과 로컬 증빙을 보존한다.

선정된 소스마다 큐 ID·씬/컷·source in/out(없으면 후보 범위임 표시)·작품 사용 시점·루프 가능 구간·전경/배경·대사 회피/덕킹 의도·전환 의도·권리·크레딧·파일 핀을 SND와 납품에 넣는다. 재생 속도/trim/mix를 실제 적용했다고 가장하지 않는다. 여러 큐가 같은 파일을 써도 사용 구간은 큐별로 구분한다.

등록 순서·단계별 준비·변경 영향의 정본은 [프리 사운드 통합 계약](../../docs/design/11-sound-sourcing-integration.md)이다. 소스 원장의 cue_ref/use_stage/rights_ref/review_ref는 감독이 확인한 현재 등록 핀으로 채우고, 후보/계획을 실제 미디어 준비와 구별한다. 오케스트레이터가 실제 프로젝트 원장에 기존 ID/버전/의존 핀으로 등록하고 production projection의 audio_cues/asset closure에 반영한다. sound-designer는 기존 writer 소유권에 따라 보고서로 납품하며 직접 원장을 쓰지 않는다. 포스트에는 **실제 파일 + 큐시트/소스 원장 + 권리 증빙·정확한 크레딧 + 미해결 사항**을 넘긴다. 파일 전달은 라이선스의 원본 재배포/수령자 권한 범위 안에서 한다.

완료 판정은 “설계 완료”와 “필수 소스 확보 완료”를 분리한다. required=true인 모든 큐가 실제 로컬 파일·권리 확인·기술 검사·최종 파일 청취·선정 근거와 연결되어야 확보 완료다. 하나라도 미확보면 partial/blocked와 정확한 재개점을 반환한다. 포스트의 실제 배치·편집·믹싱·마스터 검수는 별도 단계이며 가짜 수령 확인은 만들지 않는다.
