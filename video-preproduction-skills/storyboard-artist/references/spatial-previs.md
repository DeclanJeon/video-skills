# 공간 검증이 필요한 스토리보드

**적용 시점:** 콘티의 카메라·행동 배정 뒤, 패널 이미지 고정 전. 이야기 이해에 필요한 반복 공간의 방향, 접촉·인계, 가림 또는 카메라 경로가 평면 패널만으로 판정되지 않으면 감독에게 프리비즈를 요청한다. 단순한 2D 콘티·정면 설명 컷은 자동으로 3D에 보내지 않는다. 텍스트만 허용되면 프리비즈 사양과 미검증 항목만 반환한다.

1. **룩·공간·동작 분리.** 인물·장소 바이블은 외형의 기준이다. 카메라 담당은 같은 세트의 월드 좌표·앵커, 카메라 위치·타깃·렌즈, 컷 사이에 유지/변경될 상태를 기록한다. 가져오는 것은 레퍼런스의 작업 패턴뿐이다. 브랜드, 모션 캡처와 특정 렌더 모델은 필수값이 아니다.
2. **한 세트부터.** 빠른 인터랙티브 구도 탐색을 명시적으로 원할 때 Three.js 대역을 선택할 수 있다. 실제 공간·가림·경로를 확인하거나 프리비즈 실행을 맡았으면 감독이 Blender 공간 검증 경로를 선택한다. 접촉/소유권이 의미를 바꾸면 앞·접점·뒤 상태와 필요한 손/소품 대역을 추가한다. 추정 좌표와 단순 프록시로 해부학·최종 연기까지 통과시킬 수 없다.
3. **시트를 찍는다.** 기존 컷·패널 ID와 원래 시각을 보존한다. 패널 → 장면·카메라·샷 로컬 프레임(또는 전역 프레임 기준을 명시) → PNG 매핑을 기록한다. 우선 핵심 카메라 상태를 실제로 렌더해 방향·가림·홈/소품 가독성을 본다. 실패한 컷만 보완하되 같은 카메라를 참조한 패널은 함께 다시 확인한다. 전체 요청 프레임을 실제로 열어 보기 전 완료 처리하지 않는다.
4. **두 종류의 결과 구분.** 프리비즈 PNG·시트는 구도·연속성의 증거이자 패널 제작 참조다. 최종 이미지의 인물·룩, 손의 실제 접촉/연속 동작과 정식 QA3 판정은 별개다. 매니페스트와 버전 핀을 반환하고 `.blend`·실제 검사 파일·미검증 항목을 함께 넘긴다. 프리비즈 패널을 보지 않은 최종 이미지나 비디오의 근거로 쓰지 않는다.
