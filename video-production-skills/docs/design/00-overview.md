# Video Production Skills — 설계 초안

상태: 방향 합의 및 상세 설계 초안. 스킬 구현·설치·공급자 제출은 아직 수행하지 않음. 프리프로덕션 패키지는 변경하지 않는다. 상세 계약은 [01 인계](01-batch-contract.md), [02 참조](02-reference-continuity.md), [03 실행](03-execution-recovery.md), [04 QA](04-qa-handoff.md), [05 수락 사례](05-validation-decisions.md)가 소유하며, 본 문서는 요약이다.

## 목표와 경계

검수된 프리프로덕션을 받아 실제 영상·음향 소스를 생성하고, 테이크·연속성 검수를 통과한 소스와 사용 구간을 포스트프로덕션에 넘긴다. 최종 편집·합성·믹싱·출판은 별도 범위다. 흐름 검증용 러프 연결본은 검수 산출물이지 최종 마스터가 아니다.

## 사용자 확정 요구

- 여러 클립을 하나의 배치 큐로 관리하고 승인된 범위 안에서 모두 처리한다.
- 필요에 따라 이전 클립 및 다른 관련 클립을 참조한다.
- 캐릭터와 설계된 에셋 등 프리프로덕션 내용이 생성 결과에 반영되어야 한다.
- 개별 클립의 품질뿐 아니라 전체 영상 흐름과 접합을 유지한다.

## 구조 제안

총괄 `production-supervisor`가 큐·승인·상태를 단일 기록한다. `generation-operator`는 기존 공급자 장비를 사용하고, `take-reviewer`는 개별 결과, `continuity-reviewer`는 참조·접합·전체 흐름을 검수한다. `production-handoff`는 채택 소스·사용구간·음향 상태·후반 작업 사항을 묶는다. 독립 검수가 실제로 수행되지 않으면 자체 검수라고 표시한다.

## 배치와 참조 그래프

편집 순서와 생성 순서는 별도다. 생성 순서는 참조 의존 그래프의 위상 순서로 결정한다. 준비된 독립 노드만 공급자 동시 실행 한도 및 승인 범위 안에서 병렬 처리한다. 실행 권한은 배치 범위·각 시도·참조 전송 범위와 대조한다.

각 노드는 clip ID, shot/panel ID, 설계 버전·해시, 필수/선택 참조, 시작/끝 상태, 참조 사용/제외 속성, 실제 지원 입력 역할, 시도·작업 ID, 채택 테이크, 사용 구간 및 검수 증거를 가진다. 기존 프로젝트 원장에 통합하며 별도 경쟁 원장을 만들지 않는다.

참조 우선순위는 승인된 원본 캐릭터·에셋 → 현재 프리프로덕션의 장면 상태·보드 → 역할별 채택 테이크다. 단, 의상 교체 등 승인된 장면별 상태는 해당 설계 버전을 따른다. 원본과 설계가 충돌하면 임의로 결정하지 않고 설계 담당에게 반환한다.

이전 결과만 연쇄 참조하여 얼굴·의상이 점진적으로 변형되는 것을 막는다. 이미 등장한 공간/캐릭터는 필요한 이전 채택 테이크를 추가 참조할 수 있지만, 역할·구간·버전·해시를 특정한다. 모든 참조를 무조건 첨부하지 않으며 개수·길이·외부 전송 권한을 확인한다. 필수 참조가 지원 한도를 넘으면 우선순위만으로 조용히 잘라내지 않는다.

서로가 서로의 미생성 결과를 요구하는 순환은 제출 전 검출한다. 설계 에셋 또는 먼저 채택할 앵커 테이크로 순환을 해소하는 안을 제시하고, 필수 참조 변경은 승인 없이 적용하지 않는다. 시간 점프·리버스샷은 이전 마지막 프레임을 다음 첫 프레임으로 강제하지 않는다.

## 실행 상태와 재개

`planned → blocked/ready → submitting → submitted → running → downloaded → reviewing → accepted/conditional/rejected`.

불확실한 제출은 별도 `unknown` 상태로 두고 기존 원격 기록부터 대조한다. 타임아웃을 실패 확정으로 취급하지 않는다. 제출 전에 시도 식별자·입력 핀과 실행 승인을 기록하고, 반환된 작업 ID를 즉시 저장한다. 자동 재제출·유료 전환·모델 교체는 하지 않는다.

독립 노드에만 진행을 허용한다. 필수 선행 결과가 반려/미검증이면 종속 노드는 제출하지 않는다. 조건부 채택은 미해결 사항이 종속 참조 속성을 침범하지 않는다고 검수된 경우에만 참조 가능하다. 앞선 채택 테이크를 교체하면 이를 소비한 입력·검수·결과를 영향 범위에 따라 stale로 표시한다. stale은 삭제나 자동 재생성을 뜻하지 않으며 재검수로 유지 가능 여부를 판정한다.

## 검수 게이트

1. 인계 검사: 현재 보드·프롬프트·에셋 버전, 타임라인, 누락/충돌 확인.
2. 실행 적합성: 실제 모델·계정·참조 역할·길이·음향·비용/무제한 모드와 전송 권한 확인. 텍스트 의도를 하드 제어로 표시하지 않음.
3. 개별 테이크: 실제 원본 다운로드·디코드·길이/형식·음향 상태·해시, 전구간 재생, 의도한 행동·연기·카메라·공개 순서·접지·형태 검수.
4. 접합: 필요한 전후 구간을 나란히 및 연속 재생. 인물·의상·에셋 상태·진행 방향·시선·축·조명·동작 위상·오디오·공개 순서 검사. 의도된 시간 점프는 설계와 대조.
5. 전체 흐름: 편집 순서의 검수용 러프 연결본에서 정보 중복/누락, 속도·감정·위협 변화, 반복적인 드리프트를 검토. 프레임 몇 장만으로 운동이나 전체 흐름을 통과시키지 않음.
6. 포스트 인계: 채택 파일·해시·in/out·실제 handle 용량·오디오/대사 트랙·조건부 후반 작업·사용 제한 전달. 불가능한 후반 수정을 막연히 전제하지 않음.

반려는 설계 결함, 실행 입력/설정 결함, 생성 결과 결함으로 구분한다. 설계 수정은 담당 단계로 반환하고, 재생성에는 수정 내용과 추가 실행 권한이 필요하다.

## 완료 기준과 범위

배치가 제출됐다는 이유로 완료가 아니다. 필수 소스의 채택, 해당 접합 및 전체 흐름 검수, 포스트 인계가 모두 증명되어야 완료다. 누락·blocked·unknown·rejected·stale 상태는 완료로 집계하지 않는다. 조건부 채택은 일반 채택과 별도로 집계하고, 사용자 허용 기준과 후반 처리 가능 근거를 충족해야 납품 가능하다.

공급자·모델·실행 매체는 고정하지 않는다. 기존 Higgsfield/Ludyte 등 실제 사용 가능한 장비를 재사용한다. 배치 설계 승인은 외부 전송·생성·비용·게시 권한을 부여하지 않는다.
