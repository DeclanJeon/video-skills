# 02 — 참조 그래프와 연속성

## 1. 두 그래프
- **편집 그래프**: 관객이 보는 순서와 인접 관계. 시간 점프·교차편집·회상 허용.
- **생성 DAG**: 실제 선행 채택 결과가 있어야 하는 방향성 의존 관계. 편집상 인접이라는 이유만으로 모든 노드를 직렬화하지 않는다.

예: C01의 캐릭터/공간을 재등장 C04가 계승하고 C03 동작 출구도 필요하면 C01→C04와 C03→C04를 각각 둔다. 필수 참조가 없는 인서트 C02는 준비·승인 조건을 만족하면 병렬 가능하다. 실제 목소리/상태 의존이 있으면 인서트도 독립이 아니다.

필수·선택 edge를 구분한다. 선택 참조가 없더라도 생략 이유·영향·필수 요구 충족을 확인한다. 현재 실행에서 활성화된 생성 참조 그래프는 순환이 없어야 한다. 미래 결과를 요구하는 순환은 제출 전에 검출하고 원본 에셋 또는 먼저 만들 앵커 테이크로 해소하는 안을 제시한다. 필수 참조의 제거·앵커 신규 생성은 자동 승인하지 않는다.

## 2. 기준과 상태
승인된 정체성 원본은 얼굴·고유 표지의 기준, 현재 장면별 에셋 핀은 의상·소품·장소·LOOK의 기준, 채택 테이크는 해당 시간대의 실제 자세·동작·환경 상태의 증거다. 이 세 층은 속성별로 판단한다. 장면에서 승인된 의상 교체를 과거 클립 의상으로 덮어쓰지 않는다.

이전 테이크만 연쇄 참조하지 않는다. 매 테이크를 원본/현재 에셋 핀에도 대조해 누적 드리프트를 찾는다. 자산 원본·현재 설계·선행 결과가 충돌하면 소유자에게 반환한다. 오류가 들어 있는 결과는 성공 이력이라는 이유로 다음 조건에 복제하지 않는다.

## 3. 실제 참조 결속
1. 실제 채택 원본과 사용 구간을 전구간 재생하고 필요한 음향은 청취한다.
2. 미채택 꼬리를 제외한 구간을 쓴다. 파생 참조에는 원본 ID/version/hash, source in/out/FPS 또는 PTS, 변환 버전·출력 해시를 남긴다.
3. 각 참조가 가져올 상태와 제외할 행동/카메라/대사 반복을 적는다. 단순한 “이 영상처럼”은 불충분하다.
4. 현재 모델의 실제 역할·모달리티·개수·길이·오디오 한도를 확인한다. 외부 전송 권한과 정확한 바이트를 대조한다.
5. native asset/reference ID, role, ready 상태를 확인하고 최종 선택 목록·프롬프트와 결속한다. 업로드됨 ≠ 현재 요청에서 선택됨.
6. 필요한 video/audio 역할이 없으면 blocked. 이미지나 텍스트로 조용히 바꾸지 않는다. 지원되는 대안과 차이를 제시하고 필수 계약/권한 변경 승인을 받는다.

이전 프레임을 현재 first_frame으로 무조건 쓰지 않는다. 새 앵글의 구도는 현재 보드, 선행 영상은 관련 상태를 전달한다. first/last frame 입력도 중간 운동이나 정확한 3D 궤적을 보장하지 않는다.

## 4. 접합 관계
continuous_action / angle_change / reaction / spatial_move / time_elision / cross_cut / flashback / intentional_discontinuity 중 실제 의도를 명시한다.

각 관계에 앞/뒤 shot·panel·take·구간, 마지막 포함/첫 프레임, 컷아웃/컷인 행동 위상, 유지 속성, 허용 변화와 source locator를 기록한다. 리액션의 극중 인과·시간과 관객에게 보여주는 공개 순서는 분리한다. 승인된 보드가 반응을 먼저 보여주고 원인을 뒤에 공개하면 그대로 보존한다. 승인 없는 인과 역전이나 설계상 공개 순서 위반만 오류로 판정한다. 시간 점프는 상태 변화가 설계에 의해 설명되어야 한다. 화면 좌우와 해부학적 좌우를 구별한다.

## 5. 교체와 stale
채택 테이크나 설계 revision이 바뀌면 소비 lineage로 영향 집합을 계산한다.
- 직접 소비: 해당 입력 결속·검수는 stale. 요청 중이면 취소 지원/권한을 확인하되 임의 재제출하지 않음.
- 후손: 소비한 속성과 의존의 범위로 영향 집합을 지정하고 validity=pending_revalidation으로 둔다. 재판정 전 현재 채택·후속 참조·ready·완료 집계에 사용하지 않는다. 경합 중 도착한 성공 결과도 예외가 아니다.
- 편집상 이웃: 생성 참조가 아니더라도 접합 QA 무효화.
- 전체 연결본·인계물: 포함한 take/range가 바뀌면 다시 제작/검수 필요.
- 무관한 독립 노드는 유지한다.

재검수는 결과 유지/조건부/재생성 필요를 판정한다. 유지 가능하면 현재 입력 및 영향을 검토한 근거와 새 acceptance/range revision을 기록하고, 관련 fingerprint와 QA를 새 결속으로 갱신한다. 과거 요청에 쓰인 핀은 수정하지 않는다. stale는 자동 삭제·자동 재생성이 아니다. 과거 결과·실패 기록은 불변으로 보존하고 새 revision에서 유효 판정을 기록한다.
