# 05 — 수락 사례·구현 경계·결정

## 1. 설계 결정
- D01: 공급자 중립 총괄 + 기존 장비 어댑터. 공급자별 복제 스킬을 만들지 않음.
- D02: 기존 작품 원장 단일 writer. 큐/표는 같은 스냅샷의 파생 투영.
- D03: 편집 그래프와 생성 DAG 분리. 참조의 방향·필수 여부·속성 명시.
- D04: 원본 에셋 기준을 유지하면서 실제 채택 구간을 추가 참조. 누적 drift 검수.
- D05: 원격 성공·테이크 채택·전체 흐름·포스트 인계를 별도 판정.
- D06: 부재한 독립 검수를 꾸미지 않음. self/independent 구분.
- D07: 자동 지출·무제한 재시도·텍스트로 미지원 모달리티 우회 금지.
- D08: 최종 편집은 별도. 흐름 검수용 러프 연결본만 이 범위에 포함.

## 3. 검증 단계
1. 계약/상태/그래프 순수 로컬 검사: 양성·고의 결함 픽스처, 권한 차단, 반복 재개와 중복 방지. 실제 원격 성공으로 표시하지 않음.
2. 실행 어댑터 모의 응답: timeout·pagination·unknown·partial download·busy account를 재현. 모의 결과는 명시.
3. 깨끗한 세션 행동 평가: 작업자에게 기대 정답을 노출하지 않고, 별도 검수 권한이 있을 때 평가. 실제 도구 호출 여부와 응답/시뮬레이션을 구분.
4. 권한이 있는 실제 소규모 시퀀스: 선행 참조·독립 컷·재등장·음향·경계·전체 재생을 실제로 확인. 현재는 미실행.
5. 설치/전환: 별도 승인과 준비/롤백 검증. 문서 작성 완료를 릴리스 완료로 취급하지 않음.

## 4. 기존 도구 재사용과 한계
기존 video-preproduction-skills의 원장·핀·배치/제출 검사와 creative-production의 공급자 실행·복구 절차를 검토해 연결한다. video-production-assets의 sequence_context/validate_sequence/prepare_generation_request/inspect_sequence_frames 등은 설치 경로·실제 계약·권한을 확인한 뒤 사용한다.

도구의 구조 검사는 예술적 의미·실제 시청·동일 목소리를 자동 인증하지 않는다. CLI 존재만으로 실영상 QA나 공급자 연동을 구현 완료라고 하지 않는다. 기존 도구 계약에 맞지 않는 데이터를 변환할 때는 작은 어댑터와 해당 테스트만 추가하고, 새 독립 원장이나 공급자 내부 API를 발명하지 않는다.

## 5. 남은 프로젝트별 결정
모델·공급자·계정/모드·길이·비용/시도 범위·전송할 자산·실제 감상 도구·조건부 인계 허용 정책은 작품 착수 시 확정한다. 범용 설계에 특정 유료 플랜이나 예산을 하드코딩하지 않는다. 필수 정보가 없으면 구현 상수로 추정하지 않고 실행 게이트를 닫는다.
